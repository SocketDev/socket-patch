**New finding: C50 → [#893](https://github.com/SocketDev/socket-patch/issues/893)** (bug). Artifact GC has two retention policies.
- `ArtifactReferences::after_removal` (used by rollback and remove) keeps every active patch's beforeHash blobs, so that offline rollback keeps working (#600, #559).
- `for_apply` (used by `repair` and `scan --prune`) keeps only afterHash blobs. It deletes the originals that `get` stored from `beforeBlobContent`.
- The offline rollback error then says `Run "socket-patch repair"`, but `repair` downloads only afterHash blobs (`get_missing_blobs`).
- **Proof** (debug build, run twice with identical results): with one active npm patch and both blobs present, the control `rollback --offline` exits 0 and restores the file. After `repair --offline`, `.socket/blobs` keeps only the afterHash blob, and `rollback --offline` exits 1 with `partial_failure` ("Before blob not found … Run \"socket-patch repair\"") and leaves the file patched. `scan --prune` reaches the same `for_apply` call; I verified that path by reading only, because `scan` refuses `--offline`.
- `cleanup_unused_blobs`, `cleanup_unused_archives` and `format_cleanup_result` have no caller outside their own tests. Deleting them is part of #893.
