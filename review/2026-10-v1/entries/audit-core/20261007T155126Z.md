**New finding: C58 → [#1047](https://github.com/SocketDev/socket-patch/issues/1047)** (decision). Standalone `vex` exits `2`, the global "usage error" code, on every runtime failure except "nothing attested". Those failures include `manifest_unreadable`, `manifest_not_found`, `vendor_ledger_corrupt`, `product_undetected`, `serialize_failed` and `write_failed`, all through a catch-all `_ => 2` arm.
- **Proof:** a debug build ran under `env -i` with `--json --offline`, twice, with identical results.
  - A `{not json` manifest gives `vex -O` exit 2 (`manifest_unreadable`), but `apply --check` and `vendor --check` exit 1 with the same code, and `list`, `remove` and `rollback` exit 1.
  - An empty project gives `vex` exit 2 (`manifest_not_found`), but `remove` and `repair` exit 1 with the same code.
  - Embedded `--vex` maps every failure to 1.
- **Time-sensitive:** open PR #1027 routes vex's exit-2 sites through the new `usage_error` helper, which would cement the conflation.
- The issue recommends option 1 for v5: runtime failures exit 1.
