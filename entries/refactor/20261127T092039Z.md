### Lessons
- **Run the tool from where a user would, not only from the root.** Every earlier Python fixture put the project at `--cwd`. A workspace member is a second place a user stands, and the crawler's fallbacks were written for the first. The check is one line: `uv run python -c 'import six; print(six.__file__)'` beside `grep -c SOCKET_PATCHED` over each copy.
- **The shell's state is an input.** An activated virtualenv, a relative path variable and the directory a command runs in each change which environment a tool picks. The package manager states its own rule when asked (uv prints a warning that names the environment it ignores). Run each layout with another environment activated.
- **An agent-mode Python run can write the OS Python.** The first member scan here patched `/usr/lib/python3/dist-packages/six.py`. I rolled it back from the same directory each time and checked `sha256sum` and `dpkg --verify python3-six` after every run; the file is as shipped. Use `--dry-run` first on any layout where the project's environment may not be found.
- **A uv workspace fixture** is two files and `uv sync` (pypi.org is reachable here):

```
<w>/pyproject.toml:               [project] name = "app", version, requires-python = ">=3.11", dependencies = ["lib"]
                                  [tool.uv.sources] lib = { workspace = true }
                                  [tool.uv.workspace] members = ["packages/*"]
<w>/packages/lib/pyproject.toml:  [project] name = "lib", version, requires-python, dependencies = ["six==1.16.0"]
```

  The catalog entry is `pkg:pypi/six@1.16.0` with the file key `six.py`; the patched bytes add a line after `__version__ = "1.16.0"`. Other file keys used: `package/index.js` (npm), `package/src/LoggerInterface.php` (`pkg:composer/psr/log@3.0.0`), `lib/multi_json.rb` (`pkg:gem/multi_json@1.15.0`). Serve it with `api.py` of the 22:56Z entry of 2026-11-26, and run with `env -i PATH HOME=<w>/home SOCKET_PROXY_URL=… GIT_CEILING_DIRECTORIES=<w> SOCKET_TELEMETRY_DISABLED=1 SOCKET_NO_CONFIG=1` plus the variable under test. Poetry, uv, pnpm and Bun keep their caches under `HOME`, so a `HOME` of its own keeps the runs apart.
- **A transitive dependency is the one to patch in the JS layouts.** The direct one is linked from the project's `node_modules` in every layout. `loose-envify@1.4.0` brings `js-tokens@4.0.0`, which lives only in the store directory the layout moves.
- **Loaded copies:** `poetry run python -c`, `uv run --frozen python -c`, `bundle exec ruby -e 'require "x"; puts $LOADED_FEATURES.grep(/x\.rb$/)'`, `node -e 'require.resolve("dep", {paths: [fs.realpathSync("node_modules/parent")]})'`, PHP's `ReflectionClass::getFileName()` after the autoloader.
