### Leads and issues

**L50, filed as #2310.** For a PDM project the crawler finds the environment through `.pdm-python` (or `PDM_PYTHON`). When that file is absent, ignored or stale it tries `$VIRTUAL_ENV`, `./.venv`, `./venv` and `__pypackages__`, and then reads the Python on `PATH`. PDM never installs a project there: with no saved interpreter it takes an activated venv, then `./.venv`, `./venv` or `./env`, then the project's venvs under `venv.location`, and creates one when none exists (`Project.resolve_interpreter` and `iter_venvs` in PDM 2.29.2). Two states reach the fallback.

State 1, a venv outside the project (`venv.in_project = false`) that `.pdm-python` does not name:

```
$ export PDM_IGNORE_SAVED_PYTHON=1
$ pdm run python -c 'import six; print(hasattr(six, "SOCKET_PATCHED"), six.__version__, six.__file__)'
False 1.16.0 <home>/.local/share/pdm/venvs/p2-5hYsFcQL-3.11/lib/python3.11/site-packages/six.py
$ socket-patch scan --mode agent
Found 25 packages (25 python)
Applied 1 patch.
Patched 1 package, fixing 1 vulnerability (1 high).                              (exit 0)
$ pdm run python -c '…'
False 1.16.0 <home>/.local/share/pdm/venvs/p2-5hYsFcQL-3.11/lib/python3.11/site-packages/six.py
$ dpkg --verify python3-six
??5??????   /usr/lib/python3/dist-packages/six.py
$ socket-patch apply --check
Patches are in sync (1 patch checked).                                           (exit 0)
$ socket-patch vex --product pkg:generic/app@1 -O - | jq -c '.statements[] | {status, impact_statement}'
{"status":"not_affected","impact_statement":"Patched via Socket patch eeeeeeee-0000-4000-8000-000000000001"}
```

`socket-patch apply` over a committed `.socket/` does the same: `1 of 1 targeted patch applied`, exit 0, the OS copy patched. Three ways in, each run: the variable above (it lasts as long as it is set), `.pdm-python` absent (`git clean -fdx`; PDM's templates git-ignore the file), and `.pdm-python` naming a venv that was deleted. The last two end at the next PDM command, which saves the file again. From then on `apply --check` exits 1 and `rollback` keeps the record with a warning that names `rollback pkg:pypi/six@1.16.0 -g`, which is right; the OS copy stays patched until the user runs it.

State 2, a checkout before its first `pdm install` (`pyproject.toml`, `pdm.lock`), with a second patch in the catalog for an OS package the project does not declare:

```
$ socket-patch scan --mode agent --dry-run

  CRITICAL  httplib2@0.20.4  CVE-2026-0002
```

The same checkout with a `uv.lock` in place of `pdm.lock` reads nothing from the OS Python: `[skip] pkg:pypi/six@1.16.0 (not installed; run your package manager's install first, …)`.

The cause is in core `crawlers/python_crawler.rs`: `pdm_project_site_packages` (lines 881 to 914) returns `None` with no usable saved interpreter, `managed_or_local_site_packages` (lines 749 to 803) never looks under `venv.location`, and `local_sites_with` (lines 3613 to 3650) has a "never the OS Python" line for Pipenv, uv, Poetry and pixi and none for PDM. The class was fixed one manager at a time: PDM's saved interpreter (#502, b0a32db3), Pipenv (#504, #947), uv (#964, 00df0c42), Poetry (#1023, 83969ec3). A unit test, the twin of `poetry_fresh_checkout_has_no_env_and_no_global_fallback`, fails on `main` and the Poetry one passes; the issue has it. The contract's paragraph on projects with no environment says such a project "installs into the interpreter on `PATH`" and lists `pdm.lock` among the locks that leave the crawl unscoped. The planned fix changes that for PDM, so the issue asks a maintainer to say so if PDM should keep the fallback. Reading PDM's own venvs stands either way.

### Lessons
- **"Needs tool X" is a claim to run.** Three entries said this sandbox has no PDM, Pipenv or Hatch. `.github/workflows/ci.yml` shows the suites bootstrap them from PyPI, and `tests/e2e_vex_build/pdm.rs` holds the pins a release needs. This works here in under a minute:

```
uv venv <s>/tools --python 3.11
uv pip install --python <s>/tools/bin/python pdm==2.29.2 'hishel<2' 'unearth<0.19' pip==24.0 pipenv==2026.8.0 hatch==1.18.1
```

  Without the two pins PDM 2.29.2 dies with `module 'hishel' has no attribute 'SyncSqliteStorage'`, then `super(type, obj): obj must be an instance or subtype of type`. Link only the tool into a `bin` directory on `PATH`: with the tool venv's `bin` on `PATH`, its `python3` becomes "the Python on `PATH`".
- **A package manager's commands rewrite its own state.** `pdm run` saves `.pdm-python` again, so asking PDM what it imports before the scan repaired the state under test and the first absent-file run came back clean. Run the scan first, then ask the tool.
- **Pass the variable under test to the tool as well.** My helper for package-manager commands unset `VIRTUAL_ENV`, so two activated-venv runs compared a scan with the variable against a PDM without it and looked like defects. Rerun with the variable passed through, both are clean.
- **Guard the OS Python.** Six wet runs patched `/usr/lib/python3/dist-packages/six.py`. A copy taken before the first run, `cmp` after every rollback and `dpkg --verify python3-six` at the end: the file is as shipped. A rollback run after PDM saved `.pdm-python` again leaves the OS copy patched (it says so); restore it from the copy.
- **The harness**, around the stand-in API of the 22:56Z entry of 2026-11-26 and the `six` catalog of the 08:55Z entry:

```sh
pm() { ( export HOME=$W/home PATH=$W/bin:/usr/local/bin:/usr/bin:/bin PDM_CHECK_UPDATE=0; [ -n "$KEEP_VENV" ] || unset VIRTUAL_ENV; "$@" ); }
sp() { local extra=(); while [[ "$1" == *=* ]]; do extra+=("$1"); shift; done
  env -i PATH=$W/bin:/usr/local/bin:/usr/bin:/bin HOME=$W/home SOCKET_PROXY_URL=http://127.0.0.1:<port> GIT_CEILING_DIRECTORIES=$W SOCKET_TELEMETRY_DISABLED=1 SOCKET_NO_CONFIG=1 "${extra[@]}" socket-patch "$@"; }
loaded() { pm pdm run python -c 'import six; print(hasattr(six, "SOCKET_PATCHED"), six.__version__, six.__file__)' | tail -1; }
copies() { for f in $(find $W -name six.py) /usr/lib/python3/dist-packages/six.py; do echo "$(grep -c SOCKET_PATCHED $f) $f"; done; }
```

  `$W/bin` holds links to `pdm`, `pipenv`, `hatch` and the built `socket-patch`. A PDM project is a `pyproject.toml` with `dependencies = ["six==1.16.0"]` and `[tool.pdm] distribution = false`; `pdm.toml` with `[venv] in_project = false` moves the venv out. A Pipenv project is a `Pipfile`; a Hatch one adds `[tool.hatch.envs.default] skip-install = true` and its own `dependencies`.
