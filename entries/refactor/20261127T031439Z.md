### Leads and issues

**New: L43, filed as #2301.** With `--manifest-path` (or `SOCKET_MANIFEST_PATH`) naming a manifest that is not inside a `.socket/` directory, the manifest's own directory is the artifact directory; for a bare file name that is the project root. The cleanup of `repair`, `scan --prune`, `scan --sync`, `rollback` and `remove` then sweeps `blobs/`, `diffs/` and `packages/` there as its own stores: every regular, non-hidden file directly in `packages/` and `diffs/`, and every one in `blobs/` that is not a referenced blob, is deleted, and an emptied directory with it. The run exits 0.

```
$ mkdir -p app/packages/web && cd app && git init -q
$ echo '{"compilerOptions":{"strict":true}}' > packages/tsconfig.base.json
$ echo '# Packages' > packages/README.md
$ echo '{"patches":{}}' > socket-patches.json
$ socket-patch repair --offline --manifest-path socket-patches.json
No patches in manifest; nothing to download.

Removed 2 unused package archives (47 B freed)

Repair complete.                                            (exit 0)
$ ls packages
web
```

No network is needed. The contract documents the layout ("a manifest file elsewhere (`state/patches.json`, `/etc/socket/manifest.json`) relocates only the manifest and its lock/artifact directory"), and its own example loses `state/packages/index.json` the same way. With a patch API, the first `scan --mode agent --prune --manifest-path socket-patches.json` of a project that has no manifest yet deletes the two files. A hosted `scan --prune` does it when the manifest file exists. `rollback` over an empty manifest says there is nothing to roll back and deletes them anyway. `scan`, `apply`, `list` and `vex` delete nothing, and the default `.socket/manifest.json` layout is not affected.

The cause is two rules that are each right for `.socket/`: `socket_dir_of` (CLI `args.rs`, line 767) returns the manifest's parent, or `--cwd` for a bare name, and `ArtifactReferences::sweep` (core `manifest/cleanup_blobs.rs`, line 86) treats the three directories under it as "authoritative socket-patch state". The class was fixed twice before, one site each: the lock guard removes an emptied `.socket/` only when the directory is "literally named `.socket`: `--manifest-path` can point the lock at an arbitrary user directory" (`prune_empty_socket_dir`, core `patch/apply_lock.rs`, since #247), and the sweep refuses a linked artifact directory. The sweep itself got no such gate. A unit test that hands the sweep a project root fails on `main`; the issue has it. The planned fix: outside a directory named `.socket`, a pass removes only files that carry socket-patch's own artifact names (64 hex characters in `blobs/`, `<uuid>.tar.gz` in the two legacy stores).

- **Run every layout the contract documents, with the user's files beside it.** The flag table says a manifest may live at `state/patches.json`.
