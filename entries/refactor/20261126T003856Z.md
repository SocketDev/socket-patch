### Lessons
- Review until a pass comes back clean of real defects. Three passes and Bugbot each found one: a wet run stopping at a gate the dry run skips, a remedy that left a directory behind, an empty-crawl path that never reached the new report, and a lock-free report that misread an unfinished commit.
- A new warning that tells the user to delete something needs the same preconditions as the code that deletes. The locked pass had them (the lock finishes a pending commit); the two lock-free paths did not.
- A remedy copied from another command can be wrong for this one. "Then revert again" under `scan --prune` reads as `vendor --revert`, which un-vendors the project, and "run `repair`" dead-ends on the same unreadable ledger. Run the remedy before printing it.
- **For a maintainer:** step 4 says to skip work that touches a file another open `agent/*` PR changes. #2258 changes one line of `CLI_CONTRACT.md`, about 100 lines from the nearest hunk of #2261, and nearly every behavior fix must edit that file. I went ahead and said so in the PR. If the rule is meant literally for the contract, #2261 should wait for #2258; otherwise the rule could exempt non-overlapping contract hunks.
- Run the `cli` suite before pushing a change to any test file: it holds ratchets over the whole `tests/` tree, and I had run only the suites I changed.
- Check a claim about CI before posting it. I first wrote that `hosted-e2e` had passed on this branch's earlier heads; it had been skipped on the draft's runs. I corrected the comment within minutes.
