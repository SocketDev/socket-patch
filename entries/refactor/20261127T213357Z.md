**New: L55, filed as #2318.** An agent-mode run ends with `Commit .socket/ to keep the patches`. What it writes there is compared byte for byte with a hash on every later run: the blobs under `.socket/blobs/`, and for Go the patched module copy under `.socket/go-patches/`. Neither tree carries a `.gitattributes`, so Git's line-ending conversion applies to them. Run with git 2.43.0 and Go 1.24.7, a Windows checkout stood in for by `git clone -c core.autocrlf=true`:

```
$ socket-patch scan --mode agent                 # npm, then: git add -A && git commit
Applied 1 patch.
Next steps:
  1. Commit .socket/ to keep the patches.
  2. Run `socket-patch apply` after every `npm install`, locally and in CI. A fresh install removes the patches.
$ git clone -c core.autocrlf=true <w>/a win && cd win       # and a fresh install
$ file -b .socket/blobs/*
JavaScript source, ASCII text, with CRLF line terminators
JavaScript source, ASCII text, with CRLF line terminators
$ socket-patch apply
Error: Failed to patch pkg:npm/left-pad@1.3.0: Cannot apply patch: package/index.js - Hash verification failed before patch: blob ./.socket/blobs/ac712f73… is corrupt (its content hashes to 1b4192c2…). Run `socket-patch repair` to download it again.
Summary: 0 of 1 targeted patch applied, 0 already patched, 1 failed, 0 not found on disk       (exit 1)
$ socket-patch repair && socket-patch apply      # works in this clone
$ git add -A && git diff --cached --name-only | wc -l
0                                                # Git: "LF will be replaced by CRLF the next time Git touches it"
```

A plain clone of the same repository applies with exit 0. Three more outcomes are in the issue:

- `apply --offline` and `repair --offline` exit 1 on the converted clone; nothing recovers it without the patch API.
- A project with `* text=auto` in `.gitattributes`, or a committer with `core.autocrlf=input`, and a patched file that has CRLF endings: the commit stores the blob with LF, and a plain Linux clone with the default configuration fails the same way.
- Go. The build of a fresh `core.autocrlf=true` clone prints `PATCHED x`. `apply --check` exits 1 (`stale copy … Run socket-patch apply to regenerate them`) and `vex` exits 1 with no document. The remedy, `socket-patch apply`, exits 1, deletes all 18 files of the committed copy and takes the `replace` out of `go.mod`. The next `go run .` prints `x`. `scan --mode agent` ends the same way.

The class was fixed tree by tree in the other modes, and the agent store was left out: `<uuid>/.gitattributes` for vendored npm, PyPI and gem artifacts (e76cb9b3, #1541), `* -text` for the three JVM trees and the hosted Gradle script directory (0685ba8c, which closed #429, the same failure for Gradle). #2052 made `repair` detect a converted blob, which treats one clone. ### Lessons
- **Clone what you told the user to commit.** Every earlier fixture was the directory the scan ran in. A second machine gets the tree through Git, and Git has three inputs of its own: `core.autocrlf`, `core.eol` and the project's `.gitattributes`. The check is `git clone -c core.autocrlf=true`, then every verifying command, then `git add -A && git diff --cached --name-only` after the printed remedy.
- **A remedy that says "then commit it" can be tested.** Run it and ask Git what there is to commit. Here the answer was nothing, twice.
- **A blob with CRLF endings breaks on Linux.** The package file has to have CRLF, and the project a `* text=auto` rule. The control is the same package with no rule.
- **One build can carry many mutants.** A hidden `spmut(n)` in core reads an environment variable, each gate tests it, and the harness passes the variable through (it removes `SOCKET_*` names only). The whole table cost one build of the CLI suites and one of core's unit tests.
- **Do not export `CARGO_TARGET_DIR` to the Cargo suites.** Agent-mode `apply` and `rollback` delete the fingerprint directories of the crates they patch in every build directory they can find, and `CARGO_TARGET_DIR` is one of them (core `utils/cargo_build_cache.rs`). The Cargo suites patch fixture crates named `itoa`, `ryu` and `cfg-if`, which this workspace depends on too. With the variable exported, as the register's first note told every run to do, the cargo call after one of those suites recompiled `reqwest`, `wiremock`, `rustls`, core and the CLI: three minutes each time. Unset, the default is the same directory, the suites no longer reach it, and a core run after a CLI run rebuilt nothing. The note is corrected. The harness does not remove the variable from a child's environment; CI never sets it for tests, so this costs developers and agents only, and I did not file it.
- **A surviving mutant is a lead, not a finding.** Twelve of the fourteen passed at least one suite I had picked for them. Each of those suites tests something else, and another suite that does claim the gate went red. Only mutant 12 passed everything, and only because of the order of two directory names.
- **The fixture vendor service takes cache roots.** `Server::project_with_env(dir, &[("GOMODCACHE", <dir>)])` builds the artifact from a real module; with no cache it builds a stand-in. My holder test reads `ZZ_DIRS` as `<dir>[,KEY=VALUE…]` separated by `;`.
- **`rollback` with no target removes every patch from the manifest.** I ran it as a control in the fixture I was about to clone. Use `rollback <purl> --preserve-state`, or commit first.
