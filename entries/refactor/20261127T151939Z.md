The cause is one function, `GradleHome::resolve` (core `gradle/home.rs`, lines 52 to 83). It reads `-Dgradle.user.home` from `GRADLE_OPTS` and `JAVA_OPTS` only, and its fallback is the passwd home, where Gradle's is the `user.home` system property. `home_mismatch_with` (core `crawlers/gradle_cache.rs`, lines 543 to 565) repeats the two-variable list, so the `gradle_user_home_differs` note names the passwd home in states where Gradle does not use it. The class was fixed one site at a time: the Gradle lookup learned the passwd home (#646, 0685ba8c), and the Maven lookup learned `-Duser.home` in `MAVEN_OPTS` (#423, ca6dc059). ### Lessons
- **A place the tree calls right is a hypothesis too.** #2312 held up `GradleHome::resolve` as the lookup that follows the JVM. It follows the passwd home and nothing else. When an issue cites a good copy, run the good copy.
- **The JVM has three option variables of its own, and they bracket the command line.** `JAVA_TOOL_OPTIONS` and `JDK_JAVA_OPTIONS` come before it and `_JAVA_OPTIONS` after it. A tool's launcher variable (`GRADLE_OPTS`, `MAVEN_OPTS`) is only the middle. Any lookup that reads a `-D` from one variable is worth running with the other four.
- **Take the stale copy away before a "not found" run.** `/root/.gradle` had gained the artifact from the default-home run, so every later state would have said `Found 1 package`. Move the module directory aside, run, and put it back. Compare `ls -a /root/.gradle` before and after the run; this one left it as found.
- **The Gradle fixture.** A `build.gradle` with `plugins { id 'java' }`, `repositories { mavenCentral() }`, `dependencies { implementation 'javax.inject:javax.inject:1' }` and

```groovy
tasks.register('cp') { doLast { configurations.runtimeClasspath.files.each { println "CP " + it } } }
```

  plus a one-line `settings.gradle`. `gradle --no-daemon -q cp` takes about ten seconds and prints the jar on the classpath. Gradle needs the session's `JAVA_TOOL_OPTIONS` (the proxy flags), so append the property under test to that value for Gradle and pass socket-patch the property alone. The catalog and the stand-in API are the Maven ones of the 12:55Z entry (the jar comes from Maven Central with `curl`). The marker count is `unzip -l <jar> | grep -c SOCKET_PATCHED` over every `javax.inject-1.jar` under the work directory, `/root/.gradle` and `/root/.m2`.
- **The Yarn fixture.** A root `package.json` with `"workspaces": ["packages/*"]`, members that depend on `js-tokens` 3.0.2 and 4.0.0, and `yarn install`. The catalog's `before` bytes are the installed `index.js` of each version (file key `package/index.js`), and `after` adds a comment line.
- **A probe test goes in and comes out.** `git diff > probe.diff`, then `git checkout -- <file>`, before any other work in that checkout.
