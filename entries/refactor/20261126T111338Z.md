**#1836, confirmed.** `get --json` in agent mode, for a free user with two patches for one package, exits 1 with `status: selectionRequired` and lists the candidates in `options[]`. Each option's `vulnerabilities` array is built by iterating a `HashMap` unsorted, so its order changes from run to run. The fixture is files only: `node_modules/left-pad`, a `package-lock.json`, and a local server that answers `GET /patch/by-package/…` with two free patches of four advisories each. Eight identical runs:

```
$ socket-patch get pkg:npm/left-pad@1.3.0 --mode agent --json --proxy-url http://127.0.0.1:18836
run 1 exit=1 sha=9e89561b7b5c  [['ykkk','yddd','yaaa','yggg'], ['xkkk','xggg','xddd','xaaa']]
run 2 exit=1 sha=d572bcf58cfc  [['yddd','yaaa','ykkk','yggg'], ['xaaa','xddd','xggg','xkkk']]
run 3 exit=1 sha=b6416da11eee  [['yddd','ykkk','yaaa','yggg'], ['xggg','xaaa','xkkk','xddd']]
…
run 8 exit=1 sha=fd9d90b4f545  [['yaaa','yddd','yggg','ykkk'], ['xddd','xaaa','xkkk','xggg']]
```

Eight runs, eight documents. The lists are the advisory ids of the two options, in the order printed. `get CVE-… --json` and `get … --dry-run --yes --json` go through the same code and vary the same way (six of six distinct each).

The same object is built in two other places, and both sort by id: `agent_download::patch_event_metadata`, which carries the comment "Stable ordering — HashMap iteration is otherwise nondeterministic and consumers diff this output in CI logs", and `list`. Both also carry each advisory's `description`, which `get`'s copy leaves out. So this is the gate's first kind: three copies of one rule, and one of them gives a different answer for a patch that fixes more than one advisory.

It is the fourth kind as well. The unit test `select_json_mode_multi_free_options_serialize_vulnerabilities` says the options "must carry each patch's vulnerability details (id/cves/severity/summary) so a bot can choose without a second query", and asserts only that the call returns `Err(1)`. With every option's list emptied it passes, and so do the 162 tests of the `get` suite, three of which read `options[]`:

```diff
-                                "vulnerabilities": vulns,
+                                "vulnerabilities": vulns.into_iter().take(0).collect::<Vec<_>>(),
```
```
$ cargo test -p socket-patch-cli --lib select_json_mode
test commands::get::tests::select_json_mode_multi_free_options_serialize_vulnerabilities ... ok
$ cargo test -p socket-patch-cli --test get
test result: ok. 162 passed; 0 failed; 0 ignored
```

Two things the issue does not say:
- `show <uuid> --json` and `show CVE-… --json` print the patch's `vulnerabilities` as a JSON object straight from the same `HashMap`, so its key order also changes from run to run (six of six distinct). A parser sees the same object, a byte comparison does not.
- Nothing else varied over six runs each: the human output of `get`, `show`, `list` and `scan`, and `list --json`. `vex` differs only in its `@id` and timestamps.

The harm is small: a consumer that compares two runs of the same command sees a difference where nothing changed. The fix is small too: one helper that returns the list sorted by id, used by the three sites, and a test that reads `options[].vulnerabilities`. Adding `description` to `get`'s copy changes a JSON shape; the two other copies already carry it, and `CLI_CONTRACT.md` says only that "`options[]` lists the candidates".

### Lessons
- To find unordered output, run one command six times over one fixture and count the distinct hashes of stdout. It took a minute and found #1836 and the `show --json` map.
- A local patch server for `get` and `show` is 40 lines of Python: `GET /patch/by-package/<purl>` and `/patch/by-cve/<id>` answer `{"patches": [...], "canAccessPaidPatches": false}`, and `GET /patch/view/<uuid>` answers one patch whose `files` map carries `beforeHash`, `afterHash` and base64 `blobContent` and `beforeBlobContent`. A hash is the SHA-256 of `blob <len>\0` followed by the bytes. `get <uuid> --mode agent --save-only` against it leaves a complete agent-mode fixture.
- A bare `get` picks its mode from the project, and a fresh project gets hosted mode. Pass `--mode agent` to reach the `selectionRequired` answer.
- `serde_json::json!` does not take a block as a value. A mutation inside it has to be one expression.
- Running an integration suite rebuilds `target/debug/socket-patch` from the working tree. Revert a mutation and rebuild before the next probe.
- Four of this run's five issues were again true when written and mostly fixed since. For an October issue, grep `main` for the functions it names before anything else: #594 and #705 each took one grep to see.
