**#1926, confirmed for the prune's copy.** A crate `Cargo.lock` no longer resolves, whose copy in the registry cache holds a file at neither the record's `beforeHash` nor its `afterHash` (a line a developer added while debugging). The same copy, with the record's before-blob absent from `.socket/blobs` and then present:

```
$ socket-patch scan --sync --yes --json          # before-blob absent
pruned: []
warning: cargo_cache_patch_kept | kept pkg:cargo/itoa@1.0.11: the project no longer resolves it, but its
  copy in the shared Cargo registry cache is still patched (or could not be read to tell); run
  `socket-patch rollback pkg:cargo/itoa@1.0.11` … to restore that copy and drop the entry
$ socket-patch rollback pkg:cargo/itoa@1.0.11 --offline     # the remedy it names
Cannot roll back: src/lib.rs - Before blob not found: d43e7343… and --offline prevents fetching.   (exit 1)

$ socket-patch scan --sync --yes --json          # before-blob present
pruned: ['pkg:cargo/itoa@1.0.11']
$ socket-patch rollback pkg:cargo/itoa@1.0.11 --offline     # in a second copy of the fixture, blob present
Cannot roll back: src/lib.rs - File holds neither the patched nor the original content.       (exit 1)
```

So a cached blob that says nothing about the copy decides whether the record is kept, and the warning calls a file that was read, and is not the patched one, "still patched (or could not be read to tell)". The cause is `purls_still_patched` in the CLI's `ecosystem_dispatch.rs`: it takes `MissingBlob` as "still patched", and core's `verify_file_rollback` returns `MissingBlob` before it compares the file with the `afterHash`. The PyPI keep goes through the same function. Rollback's other-scope check (`patched_in_other_scope`) compares the hash itself, so it would not keep this copy; I read that and did not run it. The issue's second case, npm's LF-shebang form of a patched bin with the blob gone, I also only read. The harm is small: a record that stays, and a remedy that fails. One rule beside `verify_file_rollback`, where the hash decides as it already does when the blob is present, is the fix the issue proposes.
