**New: L36, filed as #2289.** `scan --mode vendored`, `get --mode vendored` and `vendor` refuse a PyPI package or a gem whose installed copy holds the patched file at bytes that are neither side of the patch, and report it as not installed. The usual way into that state is an agent-mode project whose patch was superseded: the virtualenv holds the older patch's output.

```
$ socket-patch apply --check --offline
Patches are in sync (1 patch checked).
$ socket-patch scan --mode vendored --yes --dry-run
[dry-run] Would download and vendor 1 patch. No changes made.                    (exit 0)
$ socket-patch scan --mode vendored --yes
  pkg:pypi/six@1.16.0: installed content differs from patch baseline; the patched content will be vendored
Vendored 0 packages; 1 not installed.
Error: Cannot vendor pkg:pypi/six@1.16.0: no installed package found on disk    (exit 1)
```

The same project with `six.py` pristine, at the patch's own output, or not installed at all vendors. So does `vendor --force`, and so does npm with its installed file at other bytes (pinned by `scan_vendor_annotates_mismatched_baseline_and_vendors_anyway`). A gem behaves like PyPI. The cause is `CandidateGates::judge` (`vendor.rs` line 3283): the installed-variant probe drops a candidate whose file matches neither hash even when it is the only record for the package, and the dropped purl is then reported from the `unmatched` list. #825, #1713 and #2143 each let one cause through by name (an older uuid in the vendor ledger, a hosted PyPI pin, a hosted gem pin). A prototype that drops the `hosted_pinned` condition from `superseded_install` and `hosted_gem_install` vendors all the failing cases; it was not kept. Three unit tests pin today's narrower rule and are named in the issue. `scan --mode agent` and then `scan --mode vendored` is a way out today.

### Lessons
- **Vendored mode runs on files alone.** A vendorable project is a lockfile, a `.socket/manifest.json` record (`uuid`, `exportedAt`, `files: {<key>: {beforeHash, afterHash}}`, `vulnerabilities`, `description`, `license`, `tier`) and the two blobs under `.socket/blobs/`, named by their git-blob sha256 (`sha256("blob <len>\0" + bytes)`). File keys: `package/index.js` (npm), `six.py` (PyPI), `src/lib.rs` (Cargo), `src/f.php` (Composer), `lib/demo_gem.rb` (gem). Nothing needs to be installed: the fixture server builds a stand-in package when it finds no copy.
- **The vendor service is the repository's own fixture.** A throwaway ignored test in `crates/socket-patch-cli/tests/` (never committed), 20 lines: `#[path = "prebuilt_common/mod.rs"] mod prebuilt_common;`, then for each directory in an environment variable call `prebuilt_common::Server::project(dir)`, write `server.uri` to `<dir>.uri`, keep the servers in a `Vec`, and sleep until a stop file exists. `cargo test --test <name> --no-run` builds it in 2.5 minutes; run the binary with `--ignored --nocapture`. Point the CLI at it with `SOCKET_VENDOR_URL=<uri>`. The server reads the manifest once at start, so copies of the project can be changed freely, and it answers `POST /patch/package` with every artifact.
- **Building any test rebuilds `target/debug/socket-patch`** with core's `failpoints` and `test-fixtures` features. For output quoted as "built from `main`", copy the target directory with `cp -al` and run `cargo build -p socket-patch-cli` there (22 seconds).
- **`scan --mode vendored` needs a patch API as well:** 50 lines of Python over the same manifest. `POST …/batch` answers `packages[].patches[]`, `GET …/view/<uuid>` the record with base64 `blobContent` and `beforeBlobContent` per file, `GET …/by-package/<purl>` the search shape, and `POST …/package` forwards what the fixture server answers. Give each fixture its own uuids or its own port.
- **A PyPI fixture needs a virtualenv**, even an empty one (`pyvenv.cfg` with `include-system-site-packages = false`, `VIRTUAL_ENV` set). Without it the crawler reads this machine's own `six 1.16.0`, and the vendor gate judges that copy. That is how L36 showed up.
- **A states-by-commands matrix finds what reading does not.** `vendor.rs` and its backends are 190,000 lines. One loop (vendor, change one thing, run each command, compare the tree and the lock) covered eight package managers in ten minutes, and the two rows that disagreed with their neighbours are the two issues.
- For a message that looks wrong, `gh api -X GET search/issues -f q='repo:SocketDev/socket-patch is:issue "<the message>"'` lists the earlier one-cause fixes. Three closed issues quoting the same sentence is a root cause nobody has fixed.
