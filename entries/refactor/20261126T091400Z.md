**New: L30, filed as #2277, a decision issue.** `apply --force` skips a patch file that is missing on disk and patches the rest. `rollback` has no matching rule: one absent file stops the whole package before anything is restored. The fixture is files only: `node_modules/left-pad` holding `index.js`, and a manifest record whose patch lists `package/index.js` and `package/lib/gone.js`, with the blobs in `.socket/blobs`.

```
$ socket-patch apply --offline
Error: Failed to patch pkg:npm/left-pad@1.3.0: Cannot apply patch: package/lib/gone.js - File not found   (exit 1)
$ socket-patch apply --offline --force
Warning: pkg:npm/left-pad@1.3.0: 1 patch file not found on disk and skipped (--force): package/lib/gone.js
Patched packages:
  pkg:npm/left-pad@1.3.0 (via blob)                                                                      (exit 0)
$ socket-patch rollback --offline --yes
Failed to roll back:
  pkg:npm/left-pad@1.3.0: Cannot roll back: package/lib/gone.js - File not found                         (exit 1)
$ socket-patch remove pkg:npm/left-pad@1.3.0 --yes --offline
Error: Rollback failed during patch removal. Use --skip-rollback to remove from manifest without restoring files.
                                                                                                          (exit 1)
```

After both, `index.js` is still patched. `remove --skip-rollback` drops the record and leaves it patched. With `index.js` put back at its upstream bytes, as a reinstall would, `rollback` and `remove` print the same error and exit 1 with nothing left to restore. `apply --check` on the forced state says to run `socket-patch apply`, which exits 1; `vex` leaves the package out (`file_not_found`), as documented. The contract documents both halves, the `--force` skip with its `patch_files_skipped` warning and rollback's `file_not_found` failure, and not their combination, so a fix changes rollback's result in a way it doesn't settle. The issue gives three options and asks which. Not checked: how often a real install lacks a file its patch lists.

### Lessons
- A file-only agent fixture takes a minute and no network: `node_modules/<name>/{package.json,index.js}`, a `package-lock.json`, `.socket/manifest.json` with one record, and both blobs in `.socket/blobs/`, each named by the SHA-256 of `blob <len>\0` followed by the bytes. Add `patches/<name>+<version>.patch` for a patch-package project.
- A hosted scan needs three answers from a local server, under `--api-url`, `--org test-org` and an `--api-token` of the real shape: `POST /v0/orgs/<org>/patches/batch` (`packages[].patches[]`), `GET …/patches/by-package/<purl>` and `POST …/patches/package` (`results.<uuid>` with `status: granted`, `url`, `purl`, `artifacts[]`). `tests/scan/hosted_fixture.rs` has the bodies. The same server serves `--mode vendored` and `--mode agent` as far as the gate.
- To hold the lock, open `.socket/apply.lock` from Python and `fcntl.flock(f, LOCK_EX)`; the CLI uses `flock(2)`.
- An issue from the October audits is more often stale than wrong. Four of this run's five were true when written and are now mostly fixed, pinned by a test or settled by a contract line added since. Search the contract for the issue's key word before building a fixture.
- Check a sentence of the form "this cannot happen" against the code before writing it down. I had written that every note of a successful rollback carries a marker; `close()` has one that does not.
- The interesting result came from running the next command a user would run after the one the issue was about: `rollback` after the `apply --force` that #1987 mentions.
- The register fits its limit only with every collapsed row shortened; the next run will have to move the oldest Areas rows into the entries.
