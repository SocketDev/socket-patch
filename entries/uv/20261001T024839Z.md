**Tested:** main `2463257` (#277, "consolidate the v5 patching workflow", landed since the last run; CLI still reports 4.0.0). The latest release, 4.0.0, predates both the v4 uv rewriter and the v5 upstream restore, so it can't be used for first-bad checks. uv binaries: 0.0.5, 0.1.45, 0.2.5, 0.2.18, 0.2.34, 0.2.37, 0.5.31, 0.8.17, 0.12.21.

**Harness changes for v5:** hosted mode now keeps no ledger. Rollback/remove re-derive the upstream entry from PyPI's JSON API, and they need `--patch-server-url <mock>` to recognise a non-Socket origin. Vendoring requires the grant's `artifacts[].integrity.sha512`, so the mock now returns it. In the sandbox, rustls can't reach pypi.org through the proxy, so `SOCKET_PYPI_JSON_API` points at a local forwarder (`urllib` with the proxy CA). uv 0.0.5 bundles webpki roots and can't reach PyPI at all in the sandbox, so it's blocked locally.

## False positives ruled out
- "Manifest not found" from hosted rollback: the mock origin wasn't in `--patch-server-url`. It's a harness issue.
- `vendor_prebuilt_required` "tarball artifact has no sha512 integrity": the old mock lacked sha512. v5 requires it.
- `GET https://pypi.org/pypi/... error sending request`: sandbox rustls vs the proxy CA.
- Single-dep rollback and multi-clause specifier refusals are documented (CLI_CONTRACT / `upstream/uv.rs` module doc).
