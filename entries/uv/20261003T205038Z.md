## False positives ruled out
- Agent apply overwrote a real six.py whose hash matched neither beforeHash nor afterHash. That's the documented v3.4 default (`content_mismatch_overwritten`; `--strict` refuses), and it was a harness artifact (fixture bytes).
- `scan --mode vendored` failing "could not fetch details" or `redirect_revert_failed` (pypi.org) were harness gaps: no `view/<uuid>` route, and the rustls proxy. Fixed with a mock route and the forwarder.
- `vendor` (not scan) over a hosted uv project refuses `pypi_uv_source_already_exists`; only `scan --mode vendored` takes over. That's by design.
- `vex` exit 0 with `no_applicable_patches` on a clean vendored project: the fixture has no vulnerabilities.
