**Filed**
- #342: hosted and vendored pom rewrites add a second `<repositories>` / `<dependencyManagement>` when the existing one is self-closed, or has a comment between `<dependencyManagement>` and `<dependencies>`. Maven refuses the pom ("Duplicated tag") on every line, while the scan reports redirected/applied and `vex` attests `not_affected`. Reproduced on Linux (all 4 lines, twice), and on macOS + Windows (probe, vendored `<repositories/>`).
- #350: vendored `file://${project.basedir}/…` isn't URI-encoded, so a checkout path containing `%XX` (e.g. `feature%2Fx`) makes the vendored repo miss. Maven silently resolves Central's jar (exit 0, PRISTINE), and `vex --offline` attests. Reproduced on Linux, macOS and Windows × all tested Maven lines. `${project.baseUri}` fixes it (verified on 3.9.11).
