### Cells (global mode)
- **fail #440 (new)**: `scan -g` run from inside a Berry project calls `yarn global dir`. Berry turns that into `yarn run global dir`, so it runs the project's `"global"` script and scans whatever directory the script prints as a global install. This reproduces on Linux and macOS with yarn 2.4.2, 3.8.7, 4.12.0 and 4.18.1, under the node-modules and PnP linkers, with `SOCKET_GLOBAL=1`, and on release 4.0.0. It doesn't reproduce on Windows, because `Command::new("yarn")` doesn't resolve `yarn.cmd`. Probe run: https://github.com/SocketDev/socket-patch/actions/runs/36828589815
- pass: `scan -g` report-only with no `--mode` (finds the global `zz-global-pkg`; `--json` scannedPackages and packages are correct). Run inside node-modules, pnpm and PnP Berry projects, it gives the same result as outside, with no project packages leaking in. `scan` without `-g` never touches the global copy.
- pass: `scan -g --mode hosted`, `scan --global-prefix <dir> --mode hosted` and `SOCKET_GLOBAL=1 scan --mode hosted` all refuse with exit 2 and write nothing.
- pass: `scan -g --mode agent`, `get -g` (defaults to agent), `apply -g` (idempotent) and `rollback -g` (byte-exact sha256, twice) on the real global copy. `--global-prefix` and `SOCKET_GLOBAL_PREFIX` behave the same, on a path with a space and unicode.
- pass: `vex -g` attests while the patch is applied. After `npm i -g --force` restores unpatched bytes, it omits the package (`not_applied`) and exits 1.
- pass: a root-owned prefix with a non-root user (`setpriv` uid 65534). `scan -g --mode agent` fails loudly (EACCES, exit 1), and so does `apply -g`.
- pass: agent mode on yarn 2.4.2 and 3.8.7 with the node-modules linker (apply, then rollback restores the bytes). PnP on 2.4.2 (`.pnp.js`) and 3.8.7 gets the loud PnP warning in every mode (documented).

### Observations not filed
- A re-run of `scan -g --mode agent` after the EACCES failure exits 0 with "already recorded … run `socket-patch apply`" while the package is still unpatched. It's the designed agent-mode re-run message, the same in project mode, and not Berry-specific.
- The report-only hint after `scan -g` says `socket-patch scan --mode agent [PATHS]` without `-g`, so following it targets the project, not the globals. It applies to every package manager, so it's handed over to npm (#302).
- Windows: `yarn global dir` is never run, because of the `.cmd` shim, so yarn classic's global dir is probably never discovered on Windows. Handed over to yarn-classic (#304).
