### Cells
- **Packages whose tarball `bin:` differs from the registry metadata (`./dist/bin/uuid` vs `dist/bin/uuid`): fail, filed #718.** Both pins copy the registry entry's body. Yarn re-reads the tarball manifest for tarball-URL and `file:` locators, so the lock diverges.
  - Vendored: every fresh `--immutable` install fails YN0028.
  - Hosted: a plain `--immutable` install passes, but hardened mode or `--refresh-lockfile` fails YN0028.
  - Reproduced on uuid@9.0.1 (yarn 4.0.2, 4.12.0, 4.18.1) and acorn@8.11.3 (4.18.1).
  - The hosted half is a regression from #465: release 4.0.0's `::__archiveUrl` pin passes a hardened fresh install with patched bytes. Release 4.0.0's vendor flow couldn't be driven against the mock.
- A survey of 20 bin packages found 6 with a registry/tarball `bin:` mismatch: uuid, nanoid, acorn, rimraf, node-gyp-build and typescript (typescript is refused anyway as a builtin patch). left-pad, semver, js-yaml, which, mkdirp, json5, he, esprima and others match.
