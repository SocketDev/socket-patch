**Focus:** the maintainer's global (`-g`) mode request (20261001T040000Z entry). The method is a real `deno install -g` of a local entrypoint that imports `npm:is-odd@3.0.1`, in a per-run `DENO_DIR` + `DENO_INSTALL_ROOT`. The oracle is a patched `console.log('SP-PATCHED')` and running the installed shim. `DENO_LOG=debug` shows the package folder Deno resolves. There's a local batch-API stub for `scan`, and an offline manifest for `apply` / `vex` / `rollback`.

### Filed
- **#444** https://github.com/SocketDev/socket-patch/issues/444. Deno global installs keep npm deps in `$DENO_DIR/npm/registry.npmjs.org/<name>/<ver>`. `scan -g` gives `success` and never lists them, `apply -g` gives `package_not_installed`, and no `--global-prefix` (`$DENO_DIR`, `npm`, `registry.npmjs.org`) reaches that layout. On Deno 2.9.6, `deno install -g` also writes `bin/.<tool>/node_modules/.deno`, which is a decoy for local/JSR-entrypoint tools (Deno still loads the `DENO_DIR` copy). `--global-prefix` on it reports `applied` and `vex` attests `not_affected` while the tool runs unpatched. 15/15 probe cells reproduce. Not a regression (3.3.0 and 4.0.0 are the same).
