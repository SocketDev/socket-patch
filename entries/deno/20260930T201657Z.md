**Tested:** main `f6b7fb9` (CLI 4.0.0 workspace version). For regression checks, the latest release 4.0.0 and the previous release 3.3.0 from npm `@socketsecurity/socket-patch`. Deno 1.46.3, 2.0.6, 2.2.15 (LTS) and 2.9.6 (latest), from GitHub release zips in the sandbox (dl.deno.land is proxy-denied) and `denoland/setup-deno` in the probe. The probe covered ubuntu, macOS and Windows.

**Method:** real `deno cache` / `deno install` into a per-project `DENO_DIR`, then a local `.socket/manifest.json` plus before/after blobs (git-sha256), driven by `apply --offline`. The patched bytes prepend `globalThis.__SP=(…).concat(["<name>"])`, so `deno run` of a probe that imports the direct dependency prints which patched modules **actually loaded**. That's the oracle. `scan` discovery was checked with a tiny local mock (`SOCKET_PROXY_URL=http://127.0.0.1:8765`, which returns empty batches and logs the queried PURLs). `patches-api.socket.dev` is proxy-denied.

This is the first run: there was no earlier ledger and no `pm:deno` issues to re-triage.

### Cells
- **fail #373**: agent mode with a `node_modules` dir. Transitive npm deps live only in `node_modules/.deno/<name>@<ver>/node_modules/<name>`. `apply` reports them as `package_not_installed` but finishes `success` with rc 0, and `scan` never queries them. Deno loads the unpatched copy. Reproduced with `nodeModulesDir` auto and manual (package.json + `deno install`) on Deno 2.0.6 / 2.2.15 / 2.9.6, and with `true` on 1.46.3. Linux, macOS and Windows (18/18 probe cells). Releases 3.3.0 and 4.0.0 behave the same.
- **fail #374**: JSR. The crawler probes only `$DENO_DIR/npm/jsr.io`, which no Deno creates (1.46.3 and 2.9.6 checked; JSR goes to `remote/https/jsr.io/<hash>`). A `"vendor": true` project has the matching `./vendor/jsr.io/@scope/name/ver/` layout, but local apply gives `package_not_installed`, while `--global-prefix vendor/jsr.io` applies and the patched code runs. Deno 1.46.3 / 2.0.6 / 2.2.15 / 2.9.6, Linux.
- pass: direct npm deps (the top-level `.deno` symlink target) in every cell above.
- pass: agent re-apply is idempotent (`already_patched`), and rollback restores the original bytes (2.9.6 auto).
- pass: agent writes break Deno's cache hardlinks. `deno cache` hardlinks `DENO_DIR/npm/registry.npmjs.org/...` into `node_modules/.deno`, and after apply the node_modules copy has a new inode while the cache stays clean.
- pass: VEX never attests an unapplied patch. With `setup.manual: ["npm"]`, only is-odd gets `not_affected` and is-number is `package_not_found`.
- pass: `vendor` with a `pkg:jsr` patch gives `vendor_unsupported_ecosystem`. npm-in-Deno vendoring fails closed with `vendor_lockfile_missing` (deno.lock is not a supported lock), and deno.lock / package.json are untouched.
- pass: `setup` gives `no_files` in deno.json-only projects (auto / none).
- expected failure (not filed): `nodeModulesDir` none, the Deno 2 default for deno.json-only projects. npm packages exist only in the global `DENO_DIR/npm/registry.npmjs.org/<name>/<ver>`, so apply reports `package_not_installed` with `partialFailure` (rc 1). The failure is loud, and patching a shared global cache would be a design change. Recorded as a known limitation below.

### False positives ruled out
- A Deno + package.json project gets `setup` → `success`, `packageManager: npm`, a postinstall hook, and `setup --check` → `configured`, but Deno never runs root lifecycle scripts. Measured: 2.0.6 and 2.2.15 never run them; 2.9.6 runs them only with `deno install --allow-scripts` and otherwise prints "Ignored build scripts … deno approve-scripts". A fresh `deno install` therefore reinstalls unpatched bytes. This is already tracked as a baseline GAP in `crates/socket-patch-cli/tests/setup_matrix_deno.rs`, so not filed. VEX correctly reports `not_applied` afterwards.
- `setup.manual: ["deno"]` doesn't cover `npm:` packages in a Deno project (they are `pkg:npm`, so ecosystem npm), and VEX reports `ecosystem_not_setup`. Declaring `"npm"` works. That's by design: the Deno ecosystem is JSR only.
- My first runtime probe used `createRequire(import.meta.resolve("npm:…"))`, which fails on Deno ≤ 2.2 (not a file URL). That's a harness artifact, replaced by the `globalThis` marker oracle.
