## Filed
- **#1516**: #1489's renamed-copy detection fails open when it can't read the copy's identity. Three shapes:
  - a `file:` copy outside the project root (`"lp2": "file:../ext/lpdir"` or `file:../ext/lp.tgz`): `classic_copy_ref` → `normalize_rel` returns `None`;
  - a `file:` tarball whose root isn't `package/` (`left-pad-1.3.0/`): the lenient decoder strips only `package/`;
  - a non-registry URL tarball (may be intended, since the docs only promise registry URLs).

  In all of them, H/V scans exit `success` with no copy warning, in-run and lock-only VEX say `not_affected`, and `node_modules/lp2` installs unpatched. Reproduced on 1.7.0, 1.10.1 and 1.22.22. The same-name outside-root control is caught correctly. https://github.com/SocketDev/socket-patch/issues/1516
