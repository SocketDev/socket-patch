## Cells (Linux, `61cfb9b`)
- **`.yarnrc --modules-folder deps`, agent mode** → **fail, filed #493.** The package is reported `notInstalled`, and `scan --mode agent` exits 0 with `applied: 0` and no warning. `get` + `apply` exits 1 with "not found on disk". This reproduces 2/2 on each of 1.7.0, 1.10.1 and 1.22.22. VEX correctly omits the package (`package_not_found`).
- A stale `node_modules` beside an active `--modules-folder`: agent patches `node_modules`, and Node resolves `node_modules` before `NODE_PATH`, so the loaded copy is the patched one. **Not a bug.**
- Workspaces with `nohoist: ["**/left-pad"]` (copies only in the member `node_modules`): agent / hosted / vendored all patch both copies, the frozen install is patched, and vex attests: **pass** (1.22.22).
- `--max-new-patches 1` on a 2-member workspace, hosted / vendored / agent: 1 new + 1 deferred, then the re-run admits the second, and both frozen installs are patched: **pass**.
- A custom `.yarnrc registry` (private-registry host in `resolved`): the hosted rewire and offline rollback refusal **pass**. Online rollback ignores `.yarnrc` and queries `registry.npmjs.org` unless `SOCKET_NPM_REGISTRY` is set. That's documented (CLI_CONTRACT Hosted unwind, `SOCKET_NPM_REGISTRY` row), so it's a non-bug.
- Hosted over an already-installed tree: in-run `--vex` attests from the lock pin before the reinstall (documented), and an in-place `yarn install --frozen-lockfile` then installs the patched bytes: **pass**.
- A nested non-workspace project (`examples/demo/yarn.lock`) scanned from the root in hosted mode: the crawler finds its copy, but hosted reads only the root lock, so you get `redirect_yarn_classic_entry_not_found` and `status: error`. That's consistent with the documented one-project model (run once per `--cwd`). Not filed.
