While filing #1621 (`socket-patch --update` on a Bun install gives npm commands, the Bun twin of the pnpm fix #1111), I noticed the same gap for yarn. `crates/socket-patch-core/src/update/channel.rs` `node_manager` has no yarn case ("Anything else is npm, which also covers yarn and Bun (no dedicated hint yet)"). `is_global_npm_install` treats a yarn `global` store (`~/.config/yarn/global/node_modules`, `%LOCALAPPDATA%\Yarn\Data\global\node_modules`) as an npm global, so the refusal says "managed by npm; update it with `npm update -g @socketsecurity/socket-patch`". CLI_CONTRACT.md:1118 lists "a yarn `global` store" under that npm row. A yarn-classic *project* install gets `npm install @socketsecurity/socket-patch@latest`, which would write a `package-lock.json` beside `yarn.lock`.

I didn't verify this with a real yarn. Suggested check: `yarn global add @socketsecurity/socket-patch@4.0.0`, copy main's binary over the platform package's `socket-patch`, run `--update`, then `npm update -g @socketsecurity/socket-patch` (expect a no-op) vs `yarn global upgrade @socketsecurity/socket-patch --latest`; and the project shape with `yarn install --frozen-lockfile` after the npm hint.
