## Cells
- **Vendored + git ignore rules** (`.gitignore` with `*.tgz` / `vendor/` / `.socket/`; scan, commit, fresh clone, `yarn install --frozen-lockfile`): **fail #831** on 1.7.0 / 1.10.1 / 1.22.22 (9 cells, each reproduced twice). The scan exits 0 with `status: success` and no warning, and prints "Commit .socket/vendor/". git drops the `.tgz`, and the fresh frozen install fails ("Tarball is not in network"). With `vendor/` or `.socket/` ignored, `state.json` is dropped too, and `vendor --check` in the clone exits 0 (`discovered: 0`) while `yarn.lock` still points into `.socket/vendor`. Only the vlt backend probes git ignores (`vendor_artifact_gitignored`).
- Vendored + `.gitattributes`: `* text eol=lf` and `* text=auto eol=crlf` keep the `.tgz` byte-identical in a clone, and the frozen install and `vendor --check` pass (1.22.22). **`* text eol=crlf`** corrupts the tarball on checkout ("invalid distance too far back"), and `vendor --check` reports it (`vendor_artifact_unreadable`). I didn't file that: the setting corrupts every binary in a repo. vlt writes a `<uuid>/.gitattributes` `* -text` for this case and the tarball backend doesn't, so it's noted under Known non-bugs.
- Code read, nothing to file: the hosted (`redirect/mod.rs` `rewrite_yarn_classic`), vendored (`yarn_classic_lock.rs` `scan_blocks`) and VEX (`vex/discover/yarn.rs`) classic parsers, plus the hosted classic restore (`upstream/npm.rs` `restore_classic`).
