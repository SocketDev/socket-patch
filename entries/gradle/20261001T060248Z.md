## False positives ruled out
- A `verification_metadata_unavailable` 404 for junit-bom was a fixture gap: the mock serves only what's seeded in m2, and seeding `junit-bom:5.9.0/5.9.1:module` fixed it.
- `InvalidPathException` on a unicode path was the sandbox's default POSIX locale.
- A "fresh clone resolves the unpatched jar" result was two parallel harness tests sharing a work dir. It went away with `--exact`.
- Missing Windows output in the first probe was a harness bug (WSL bash), not the CLI.
- `list` with a manifest shows `verified: false` for a vendored Gradle patch, because the agent-mode file check finds no patched m2 copy. That's informational, not filed.
