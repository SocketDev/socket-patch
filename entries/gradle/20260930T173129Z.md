[agent] 2026-09-30: Gradle bug-hunt run

This is the first run. The ledger was empty and there were no `pm:gradle` issues to re-triage.

**Tested:** main `f6b7fb9` (CLI 4.0.0), latest release v4.0.0. The Gradle snippet and refusal code isn't in v3.3.0, so v4.0.0 is the first release with it. Gradle 6.9.4 (JDK 11), 7.6.6 (JDK 17), 8.14.3 and 9.8.0 (JDK 21), all on Linux.

**Setup:** the sandbox can't reach the Socket API. A small Python mock of `/v0/orgs/<org>/patches/{batch,by-package,package,view}` (shaped like `e2e_redirect_maven_build.rs`) returns a `maven2` override with `mavenSuffixedVersion=1.10.0-socket.4d5e6f70`. The "Socket repo" is a local `file://` maven2 repo that serves a marker-patched commons-text jar and the upstream pom re-versioned to the suffix. The real CLI printed the snippet, and it was pasted verbatim into real Gradle builds.

## Cells
- **Hosted, Groovy, direct dep only** (snippet + bump): pass on 6.9.4 / 7.6.6 / 8.14.3 / 9.8.0.
- **Hosted, Groovy, direct + transitive base request** (commons-configuration2 2.9.0): **fail → #347** on all four majors. Conflict resolution picks upstream 1.10.0 with exit 0. A `strictly` declaration fixes it.
- **Hosted, Kotlin DSL:** **fail → #348** on all four majors. `maven { url "…" }` doesn't compile; `url = uri("…")` does.
- **Discovery, Gradle-only project (agent / hosted / vendored scan):** **fail → #349**. `~/.gradle/caches/modules-2` is never crawled, so the scan reports success with 0 packages.
- **Vendored refusal `vendor_gradle_unsupported`:** blocked. Without a warm `~/.m2` the scan never reaches it (#349). With a warm m2 the mock run stopped at `no_local_source`, which is a mock artifact (it needs `--vendor-source build` + `blobContent`).
- macOS / Windows: not probed. All three findings are OS-independent: Gradle version ordering, snippet text, and the crawler root.
