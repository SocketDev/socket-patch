## Cells (global mode)

- `scan -g` report-only, default folder: **pass**. It finds every `~/.nuget/packages` package, with correct versions, and `--json` is sane. Linux 8, plus all 8 probe cells.
- `scan -g` vs `dotnet tool install -g`: **fail → #426**. The tool store is never crawled. `--global-prefix ~/.dotnet/tools/.store` finds 0 packages; only the per-tool `.store/<id>/<ver>` works. `apply -g` fails loudly (rc 1, not found), and `vex -g` gives `package_not_found`. Reproduced in all 9 cells (local + 8 probe), and on v4.0.0.
- `scan -g` / `apply -g` / `vex -g` with a user-level `globalPackagesFolder`: **fail → #397 (comment)**. Scan misses the real folder, apply patches `~/.nuget/packages`, and VEX says `not_affected`. Reproduced in all 9 cells.
- `scan -g --mode hosted` and `scan --global-prefix <dir> --mode hosted`: **pass**. Both refuse with exit 2 and write nothing.
- `apply -g` → real `dotnet build` → `vex -g` → `rollback -g`, default folder: **pass**. The patched bytes are used by the build, VEX attests only while applied (0 statements after rollback), and rollback is byte-exact.
- `SOCKET_GLOBAL=1`, `SOCKET_GLOBAL_PREFIX`, and `--global-prefix` with spaces + unicode: **pass** (same discovery as `-g`).
- `scan -g` from inside a packages.config project: **pass**. The project's `packages/` doesn't leak into `-g`.
- Project-mode scan (no `-g`): **fail → #427**. It lists the whole `~/.nuget/packages`, and `scan --mode agent` patches an unrelated cached package (`serilog`) and VEX attests it as a subcomponent of the product. Linux 8, 2/2 runs, and the same on v4.0.0.
- Unwritable global dir (root-owned prefix / Program Files): **blocked**. The sandbox runs as root; this needs a probe with `chmod` as the runner user.
