## Cells

- Unwritable global packages folder (non-root, root-owned `chmod a-w`), project mode `NUGET_PACKAGES` and `apply -g` `~/.nuget/packages`: **pass**. rc 1, `apply_failed` "Permission denied (os error 13)", nothing written, and VEX omits it (`not_applied`). The error names no path, which is cosmetic.
- Partially writable package (one subdir read-only, 3-file patch): **pass by design**. Two files are patched, rc 1 `partialFailure`, VEX omits it, and `rollback` restores both files (rolledBack 1). apply.rs documents partial-apply + retry as intended behaviour.
- `dotnet tool install --tool-path`: **fail → #426 (comment)**. `apply --global-prefix <tt>/.store`, `<tt>` and `-g` all give `package_not_installed`. https://github.com/SocketDev/socket-patch/issues/426#issuecomment-5930654558

- Hosted, user `nuget.config` already maps the exact id to nuget.org: **fail → #462**. The rewriter adds a second exact-id mapping, which ties with the user's. If the Socket feed is slower (stand-in `index.json` delayed 3 s), the locked restore fails NU1403 and the lockless restore exits 0 with **unpatched** bytes. Reproduced 2/2. The control (default config, same delay) passes, and at 0 ms / 500 ms the local stand-in wins.
- Vendored with the same user mapping: the config has the same tie, but restore passed (the local folder feed wins). It's listed in #462.
