## False positives ruled out

- Poetry 1.0 + pip 23.0.1 refuses the hosted wheel ("THESE PACKAGES DO NOT MATCH THE HASHES"). This is the documented pip 22.3–23.0 fragment window, and the `redirect_poetry_stale_install_risk` advisory names it. With pip 24.0 it installs.
- Vendored `--vex` on a warm unpatched venv attests, with the warning `vendored_tree_out_of_sync`. Documented in CLI_CONTRACT.md: the attestation stands on the committed artifact.
- `list` / standalone `vex` don't see hosted pins on a non-Socket origin unless you pass `--patch-server-url`. That's expected for the mock origin.
- `get CVE-…`: my mock lacked the `by-cve` route. That's a mock gap.
- `scan --vendor-source build` was removed in v5 (documented in `--help`).

## Observations (not filed)

- VEX product auto-detection emits `pkg:pypi/Pep_App.X@1.2.3` verbatim from `[project].name` (`vex/product.rs:164`). The purl spec wants PyPI names lowercased with `_` → `-`. This path is shared across PyPI managers, not Poetry-specific, and the impact is unclear.
- After rollback, `reinstall_required` says patched bytes persist "until the next package-manager install". On Poetry < 1.4 a plain `poetry install` doesn't replace them either. That's a minor wording issue.
