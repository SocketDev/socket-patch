## Cells

- **`scan -g` report-only (`--json`):** finds the global user-site `six`. Project-only packages (`iniconfig 2.0.0` in the `.venv` and lock) don't leak into the batch request. Pass.
- **`scan -g --mode hosted`, `--global-prefix … --mode hosted`, `SOCKET_GLOBAL=1 --mode hosted`:** exit 2 with "global installs have no project lockfile to redirect", poetry.lock byte-identical. Pass.
- **`scan -g --mode agent`, then a re-run:** the global copy is patched, `.venv` and lock untouched, the re-run gives `skipped`. **`get <uuid> -g`** and **`SOCKET_GLOBAL=1 get`** default to agent and give the same result. Pass.
- **`vex -g`** attests the applied global patch. Plain `vex` from the project refuses (`not_applied`, the `.venv` copy is unpatched). Pass.
- **`rollback -g`** restores the global `six.py` byte for byte. Pass.
- **Cross-scope rollback: fail → filed #450.** A project apply followed by `rollback -g`, or a `-g` apply followed by `rollback`, drops the manifest entry (and GCs its blobs) because the copy in the crawled scope is `already_original`. Exit 0, and the patched copy stays patched. 2/2 in each direction on main and on the PR #446 head. Release 4.0.0 is good. First bad commit: `d5e1815` (#231).
- **Read-only `--global-prefix`** (run as uid 65534 against a root-owned prefix): human mode prints `Permission denied` and exits 1. Pass. JSON gives exit 1 with `failed: 0`, action `added` and no error, which is #424 (Maven sibling), the same symptom on pypi. The re-run's "already recorded" skip with exit 0 is by design (it points at `apply`, and `apply` reports `apply_failed`).
- **Poetry official-installer venv** (`~/.local/share/pypoetry/venv`, Poetry 1.8.5, 47 dists): `scan -g` never crawls it. Same class as pipx → commented on #415: https://github.com/SocketDev/socket-patch/issues/415#issuecomment-5928264480
- **Apt `.egg-info` installs** (`/usr/lib/python3/dist-packages/six`) are invisible to `-g`. Already #447 (pip sibling).
- **Project scan without `-g`, Poetry venv undiscovered or not created yet:** the crawler falls back to the global interpreter and **patches it** (`added`, exit 0). That happened for the nameless `package-mode = false` + out-of-tree venv case, and for a fresh clone before `poetry install`. Poetry's venv stays unpatched. New evidence on #327: https://github.com/SocketDev/socket-patch/issues/327#issuecomment-5928252056
- **macOS / Windows:** blocked. `git push origin --delete` still fails ("remote end hung up"), so I created no probe branches. The two stale branches from run 1 remain.
