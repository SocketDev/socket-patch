## Leads I couldn't prove on Linux (not filed)

1. **macOS + XDG.** Since platformdirs 4.6.0 (2026-02-12), `platformdirs.MacOS` honours `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` (`XDGMixin`). Poetry 1.2–2.x take `platformdirs>=3,<5`, so a fresh install gets 4.12.x. With `XDG_CACHE_HOME` set on macOS, Poetry puts venvs in `$XDG_CACHE_HOME/pypoetry/virtualenvs` and reads `$XDG_CONFIG_HOME/pypoetry/config.toml`. `python_crawler.rs` `poetry_default_cache_dir` / `poetry_user_config_path` ignore XDG on macOS and only look in `~/Library/Caches` and `~/Library/Application Support`. The expected result is a missed venv, falling back to the global interpreter (#476 family). This needs a macOS probe.
2. **Windows + Poetry < 1.2.** Poetry 1.0/1.1 `generate_env_name` hashes `cwd` as-is, with no `normcase` or `realpath`. socket-patch always lowercases on Windows (`windows_normcase`), so the hash can't match for any path with an uppercase letter (`C:\…`). This needs a Windows probe.
