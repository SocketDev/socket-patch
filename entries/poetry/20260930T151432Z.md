[agent] 2026-09-30: Poetry bug-hunt run

This is the first run, so the ledger started empty and there were no `pm:poetry` issues to re-triage.

**Tested:** main `f6b7fb9` (CLI reports 4.0.0), latest release 4.0.0, previous release 3.3.0 (4.0.0 is used for first-bad checks).

**Setup:** the sandbox can't reach the Socket patch API (proxy 403), so a local mock API served a real patched `six-1.16.0` wheel (plus `jaraco.functools-3.5.0`). Every cell ran a real Poetry release: `poetry lock` / `install` / `sync` / `check --lock`, then a byte check of the installed file. macOS and Windows ran through two probe workflows.

## Cells

- **Agent, default out-of-tree venv, named project:**
  - pass: Linux 1.8.5 / 2.0.1 / 2.3.3 / 2.4.3, macOS 1.8.5 / 2.0.1 / 2.4.3.
  - **fail on Windows 1.8.5 / 2.0.1 / 2.4.3 → #329.** Reproduced on an 8.3 temp path and on a long `D:\` path.
- **Agent: nameless `package-mode = false`, `[project].name` + `[tool.poetry].name`, `in-project = false` + stray `.venv`:** **fail on every OS and version → #327.**
- **Agent lifecycle on Linux 2.3.3** (scan, idempotent rescan, `poetry sync` keeps patch): pass. rollback, repair and remove were blocked by my mock (no blob route), so these aren't bugs.
- **Hosted, Linux 2.3.3:** pass for groups (optional) + markers, transitive package, `poetry sync` / `--with`, path + url deps, superseding uuid re-pin, `--dry-run`, `get --mode hosted`, VEX, and byte-exact rollback.
- **Hosted, legacy lock 1.1 with a dotted name** (`jaraco.functools`: quoted `[metadata.files]` key on 1.1.15, normalized on 1.2.2): pass, including install and rollback.
- **Hosted and vendored, LF + CRLF locks** (install, `check --lock`, rollback exact): pass on Linux 1.8.5 / 2.4.3, macOS 1.8.5 / 2.4.3 and Windows 1.8.5. Windows 2.4.3 was still running when this entry was written.
- **Vendored, Linux 2.3.3 with path/url deps:** pass.
- **Mode switch hosted ⇄ vendored:** **fail → #328.** PyPI-wide (uv too), so a handover went to `entries/uv/`.
- **Vendored `repair` of a deleted wheel on a lock-only checkout:** fail, reproduced twice. Held for next run by the 3-issue cap (backlog 1).

- Agent VEX `ecosystem_not_setup` is documented.
