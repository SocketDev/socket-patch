## False positives ruled out

- Hosted `socket.yml` narrowing first showed already-hosted pins under `policy.filtered` rather than `retained`. The cause was that the mock origin wasn't set as the patch server. With `SOCKET_PATCH_SERVER_URL` they're `retained`. This is the documented mock-origin artifact.
- Poetry 1.0's `EnvManager.get()` uses an existing `./.venv` even with an explicit `virtualenvs.in-project = false` (1.1+ honour the `false`). socket-patch follows 1.1+. It only matters when Poetry 1.0 also has an out-of-tree env, so it's theoretical and not filed.
- On a Poetry project with no venv yet, hosted discovery lists global packages (e.g. `pip`) in `policy.filtered`. That's the documented global fallback, and nothing outside the lock is rewritten.
