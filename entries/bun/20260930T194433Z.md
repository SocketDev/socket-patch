[agent] 2026-09-30: Bun bug-hunt run

**Tested:** main `f6b7fb9` (CLI 4.0.0 workspace version). Latest release 4.0.0 and previous release 3.3.0, both from npm `@socketsecurity/socket-patch`, for regression checks. Bun 1.1.38, 1.1.45, 1.2.23, 1.3.0, 1.3.2, 1.3.4, 1.3.5, 1.3.6, 1.3.9, 1.3.10, 1.3.14, 1.4.0 and 1.4.2 (the current `latest`) from GitHub releases, on Node 22 in the sandbox. Probes ran on ubuntu, macOS and Windows.

**Method:** the patch API is unreachable from the sandbox (`patches-api.socket.dev` is proxy-denied), so I used a ~70-line Python mock with these routes: batch, by-package, the `patches/package` grant, `patches/view` with `blobContent`, and the hosted tarball route. Patched tarballs are built from the real registry tarball with a marker prepended to the main file, gzipped with mtime 0 so the sha512 is stable. The oracle is the marker in the installed file after a **fresh-checkout `bun install --frozen-lockfile`** with an empty cache, plus `node require` for the native-module case.

This is the first run: there was no earlier ledger and no `pm:bun` issues to re-triage.

### Cells
- **fail #366**: agent mode with Bun's isolated linker. Transitive packages under `node_modules/.bun/` are treated as lockfile-only: `scan --mode agent` exits 0 with `success` and doesn't patch or record them. This happens by default in fresh workspaces on Bun 1.3.14 and 1.4.2, and with `linker = "isolated"` on 1.2.23+. Reproduced on Linux, macOS and Windows. Releases 3.3.0 and 4.0.0 behave the same.
- **fail #367**: hosted and vendored mode silently discard the project's own `bun patch` (`patchedDependencies`). The fresh frozen install exits 0 with Socket's patch but without the user's. Reproduced on Bun 1.2.23, 1.3.9, 1.3.14 and 1.4.2, text lock and `bun.lockb`, on all 3 OSes. 3.3.0 and 4.0.0 behave the same. `rollback` restores it (pass).
- **fail #371**: hosted and vendored rewiring loses Bun's default trust, so `better-sqlite3`'s install script is blocked and `require` fails after a fresh frozen install. The first bad Bun release is **1.3.5** (1.3.4 passes). Confirmed on all 3 OSes. `trustedDependencies` works around it.
- commented on #356 (npm-owned): agent-mode npm aliases under Bun 1.4.2. The mixed project patches only `left-pad`, not `lp`, and VEX attests `not_affected`.
- pass: agent mode with the hoisted linker (direct and transitive), on Bun 1.2.23 / 1.3.14 / 1.4.2 × 3 OS.
- pass: hosted + `bun update` unwires the redirect, and `vex` then reports `redirect_unwired` (Bun 1.4.2).
- pass: agent `scan --global` on `bun add -g` packages (`~/.bun/install/global/node_modules`, Bun 1.4.2).
- pass: the `setup` hook (`npx …`) in a Bun-only PATH with no node/npx. Bun maps `npx` itself, and `bun install` exits 0 (1.4.2).
- pass: agent writes break Bun's cache hardlinks (rename-over write, code-verified; the cache is not written through).

### False positives ruled out
- Agent `rollback` failing with `missing_blob` came from my mock, which serves no before-blob. It's a fixture limit, not a bug.
- The esbuild postinstall that became "untrusted" after rewiring has no observable effect (its binary comes via optionalDependencies), so I used better-sqlite3 to prove the #371 impact.
- On Windows, the default-linker workspace cell had `bun install` exit 1 on the runner. That cell is inconclusive there; the explicit `linker = "isolated"` cell reproduces #366.
- On Bun 1.2.23, a new workspace defaults to the hoisted layout, so agent mode passes there. That's expected, not a fix.
