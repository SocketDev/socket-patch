### Cells
- **fail #469 (new):** Bun `bundled: true` lock entries (`"@bh/bund/is-number": ["is-number@7.0.0", "", {"bundled": true}, …]`). Hosted and vendored rewire them silently (success, no warning; npm warns `*_bundled_instance_skipped`). Bun unpacks bundled copies from the parent tarball, so the copy the parent loads stays unpatched after a frozen install. On text locks with Bun ≥ 1.2 there's also an extra patched hoisted copy that nothing loads. Vendored default `vex` attests `not_affected` and hosted `vex --no-verify` attests too. Hosted default `vex` → `not_applied` (ok). Affected: 1.1.45 (text v0 + lockb), 1.2.23, 1.3.14 and 1.4.2 (text + lockb), in both the "bundled only" and "bundled + direct" shapes. Release 4.0.0 behaves the same and also attests in hosted default `vex`: not a regression.
- **pass:** hosted → vendored takeover on a v1 workspace lock (1.3.14, hoisted). Refuses with `vendor_bun_workspace_unsupported` before any write: bun.lock, the package.json files and the file list are unchanged, and the hosted pin is kept. `--dry-run` gives `would_refuse` with exit 0, the real run `partial_failure` with exit 1. That asymmetry is documented (CLI_CONTRACT `would_refuse` row).
- **fail → #405 (commented):** vendored + isolated linker, stale tree (not reinstalled). `vex` attests from the artifact (by design) but omits the `vendored_tree_out_of_sync` warning. Hoisted emits it. 2/2 runs each, Bun 1.4.2. After a frozen reinstall the `.bun/` copy is patched and `vex` is correct. https://github.com/SocketDev/socket-patch/issues/405#issuecomment-5932538331

### False positives ruled out
- Hosted default `vex` on the bundled shape correctly refuses (`not_applied`): its installed-tree check sees the bundled copy. Only vendored, and `--no-verify`, attest.
- Vendored `--dry-run` exits 0 with `success` while the real run exits 1 with `partial_failure`, for the same refusal. That's documented.
- Vendored `vex` attesting while the installed tree is stale is by design: the artifact is the evidence. Only the missing warning is a bug.
