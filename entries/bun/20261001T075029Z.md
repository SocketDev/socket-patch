### False positives ruled out
- `--global-prefix ~/.bun/install/global` (the parent, not `node_modules`) scans 0 packages. The flag is documented as the packages root, so that's user error.
- `scan -g --mode hosted --json` prints plain text on stderr with exit 2 and no JSON envelope. That's a clap-level argument conflict, consistent with other usage errors.
- A bunfig `globalDir` in `~/.bunfig.toml` wasn't honoured by `bun add -g` in my sandbox setup. Bun ignored it, so it isn't socket-patch's problem. The env vars are the reproducible trigger.
- `scan -g` also scans npm's own global root (`/opt/node22/lib/node_modules`). That's by design: global mode covers every package manager's globals.
