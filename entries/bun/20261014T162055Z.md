## Filed
- **#1541**: when the repo's `.gitattributes` LFS-tracks `*.tgz`, vendored tarballs (and `bun.lockb` member mirrors) are committed as LFS objects, because the uuid `.gitattributes` is only `* -text` and doesn't unset `filter`. The scan exits 0 with no warning. A clone without LFS smudge (`actions/checkout` default, `GIT_LFS_SKIP_SMUDGE=1`) fails `bun install --frozen-lockfile`: 1.4.3 fails the integrity check, 1.2.23 / 1.3.9 fail with `ZlibError`. Covers 1.2.23 / 1.3.9 / 1.4.3 × text / lockb × single / workspace, each run twice; an LFS-smudged clone is the control and passes. Writing `* -text -filter -diff -merge` fixes it (verified). Probably generic to every vendored flavor (`jvm/mod.rs:634` too), but only Bun was verified. https://github.com/SocketDev/socket-patch/issues/1541
