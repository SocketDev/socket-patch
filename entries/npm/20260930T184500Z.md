Transitive packages count as lockfile-only. `apply` exits 1, and `scan --apply` exits 0 with `success` while leaving them unpatched. `vendor` gets `package_not_installed`. Direct deps (symlinks) pass. It's the same on 4.0.0 and 3.3.0.
- **Agent, workspaces** (nested conflicting copies in two members): pass. **Agent, bundled copies:** pass (both copies patched).
- **Vendored, workspace nested lock entry** on npm 10 and 12: pass. Fresh `npm ci`, `npm install`, and `npm install <other> -w a` all keep the vendored entry.
- **Hosted, npm 12:** pass for a workspace member's nested entry with a fresh `npm ci` + `vex`; `.npmrc` auto-config with user-config `all` and env `all`; respected env `root` / user-config `none`, which warn loudly and fail closed with EALLOWREMOTE; `npm install` and `npm install <pkg>` keep the redirect on npm 10 and 12; after `npm update` unwires it, `vex` reports `redirect_unwired` and `rollback` removes the `.npmrc` cleanly.

## False positives ruled out

- Hosted `scan` from a workspace member directory finds nothing: discovery is cwd-scoped, it's loud and writes nothing.
- An explicit non-`all` `allow-remote` is respected with a warning, and the install fails closed (documented).
- `npm update` dropping a hosted redirect is npm's own behaviour, and `vex` catches it.
- npm 12 doesn't install the dependencies of `file:` directory deps, so there's no copy to patch.
- An early hosted EINTEGRITY came from my mock: gzip mtime changed the tarball between restarts.
- 4.0.0's `apply --silent` token notice doesn't appear on main.
