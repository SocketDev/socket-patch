[agent] 2026-10-28: npm bug-hunt run

**Tested:** main `b787454` (unchanged since run 49), release v5.0.1 (`latest`). Linux only, with real installs on npm 10.9.4 / 12.2.1 and Node 22.22.0, against a local mock of the org patch API and patch server. No npm release newer than 12.2.1 has shipped. Probe branches are still blocked, so none were pushed.

**Cells**
- pass, add-a-file patches (index.js modified plus a new `lib/added.js`) on npm 12.2.1 with `install-strategy=linked`, against the transitive `ms@2.0.0` in `.store`:
  - agent: `scan --mode agent`, `vex`, `apply --check`, and `rollback`, which removes the added file and its directory;
  - hosted: `npm ci` installs the added file, `vex` attests, `vex` fails safe (`not_applied`) when only the added file is missing, and `rollback` is byte-exact;
  - vendored: `npm ci`, `vex`, `vendor --check`, and a byte-exact `vendor --revert`.
- **fail, new #1782**: eject (`vendor` over hosted pins) interrupted in its write window. An `LD_PRELOAD` shim signals on the Nth `rename()`.
  - SIGKILL at renames 2–6 (main and v5.0.1), and SIGINT / SIGTERM at rename 3, all leave `package-lock.json` restored to the unpatched registry entry, `.npmrc` deleted, no `.commit-journal.json` and an orphan `.socket/vendor/npm/<uuid>/`.
  - Afterwards `npm ci` installs unpatched bytes. A re-run of `vendor` reports `noManifest` with exit 0, `vendor --check` is silent with exit 0, and `vex` has nothing to attest.
  - The window is about 115–140 ms per run with one package. Reproduced on npm 10.9.4 (v3 lock) and on 12.2.1 linked with a pre-existing `.npmrc`.
- pass: the `scan --mode vendored` takeover of the same pin, killed at each of renames 1–8, stays hosted until the journal, then rolls forward.
- pass: SIGINT during the eject's artifact download (the mock delays the tarball 8 s). The download precedes the restore.

**Issues**

**False positives ruled out**
- A Ctrl-C during the eject's download is safe (it comes before any write). Added to Known non-bugs.
- `allow-remote=all` left in a pre-existing `.npmrc` after a hosted `rollback` is the documented `npm_allow_remote_left` advisory.
- `vex` without `--patch-server-url` doesn't recognize pins made against a mock origin (expected: a non-default patch server).
