[agent] 2026-10-02: handover from the Bun bug-hunt routine (#306). Not filed: the behaviour is in the npm-family agent crawler, not Bun-specific, and could be by design.

**Observation:** in agent mode, `socket.yml` path policy judges only the scan root (`--cwd`). Independent nested projects (each with its own lockfile) under the root are crawled into project `""`, so `patches.ignorePaths` / `includePaths` and the built-in `tests/` default never exclude them.

Repro (main `61cfb9b`, Linux, 2/2 runs; a local mock API; nested projects installed with Bun 1.4.2, plus a root `package-lock.json` via npm 10):
```
repo/ (.git, package.json + package-lock.json: left-pad@1.3.0)
  apps/web/       bun.lock  is-number@6.0.0
  apps/api/       bun.lock  is-odd@3.0.1
  services/legacy bun.lock  left-pad@1.3.0, is-number@6.0.0
  tests/e2e/      bun.lock  is-number@6.0.0
socket.yml: version: 2 / patches: ignorePaths: ["/services/"]
socket-patch scan --mode agent --yes --json   # at repo root
```
- Result: `success`, `policy.counts {filtered: 0, retained: 0}`, and `services/legacy/node_modules/left-pad/index.js` is patched.
- With `includePaths: ["/*", "!/*/"]` (CLI_CONTRACT: "targets only the repo-root project"), every nested project's copy is patched, including `tests/e2e` (a default-ignored dir).
- Code: `ScanPolicy::for_root` (crates/socket-patch-cli/src/commands/scan/policy.rs:141) evaluates `admits_root` once, for the cwd. Agent PATH globs (`scan 'services/**' --mode agent`) also report `filtered: 0`.
- Hosted and vendored modes are fine: `scan '*/*' --mode hosted|vendored` runs per directory, and the policy is honoured there.

Related, also generic and not filed: hosted/vendored PATH globs (`project_dirs`, scan/mod.rs:1314, `glob::glob` with default options) match dot-dirs and `node_modules`. So `scan '*/*'` visits `.git/hooks`, `.git/objects`… (printing "No packages found"), and `scan 'apps/**'` visits `apps/*/node_modules/<pkg>`. It's noise only in my runs; nothing was written there.

Your call whether either one is a bug under CLI_CONTRACT "socket.yml patch policy" → Paths.
