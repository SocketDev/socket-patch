[agent] 2026-10-01: handover from the Deno bug-hunt routine (ledger #308): agent-mode `vex` attests not_affected while other nested copies of the same name@version are unpatched

Found while testing Deno's hoisted linker. The root cause is generic npm-family, and the realistic trigger is plain npm, so this is yours to file. Nothing was filed from Deno. I searched for duplicates (#325, #405, #435, #471 are bundled / hosted / isolated / global variants) and found none covering agent mode.

**Defect.** In agent mode `vex` hashes only the **first** installed copy of each PURL: `crates/socket-patch-cli/src/commands/vex.rs:556` `let package_paths = collapse_to_first(copies.clone());`. Every other copy is ignored, while hosted-basis PURLs check every copy (`vex_consumed`). CLI_CONTRACT's verification table says agent evidence is "the installed tree". When the first copy is patched and another copy of the same `name@version` isn't, vex emits `not_affected` for a package whose unpatched copy is still loaded at runtime. The verdict depends on crawl order: revert the first copy instead and vex correctly says `not_applied`.

**Realistic trigger (real npm 10.9.4, main `61cfb9b`, Linux, reproduced 2/2).** `apply` patches every copy present, then a later `npm install` of new dependents extracts fresh, unpatched nested copies and leaves the old patched one alone:

```sh
mkdir npmdup && cd npmdup && echo '{"name":"npmdup","version":"1.0.0"}' > package.json
npm install kind-of@6.0.3 is-number@3.0.0          # nests kind-of@3.2.2 under is-number
# offline manifest + blobs patching package/index.js of pkg:npm/kind-of@3.2.2 (any free patch works)
socket-patch apply --offline                         # applied 1
npm install is-accessor-descriptor@0.1.6             # adds node_modules/is-accessor-descriptor/node_modules/kind-of@3.2.2 (unpatched)
socket-patch vex --offline -O v.json                 # exit 0, 1 statement: not_affected pkg:npm/kind-of@3.2.2
```

Copies afterwards: `is-number/node_modules/kind-of` patched, `is-accessor-descriptor/node_modules/kind-of` **unpatched**. A re-run of `apply` does patch the new copies (`applied: 2, skipped: 1`), so apply is fine; only vex is wrong.

**Deno too:** `nodeModulesLinker: "hoisted"` (2.9.7) with `kind-of@6.0.3` + `is-number@3.0.0` + `is-accessor-descriptor@0.1.6` gives two nested `kind-of@3.2.2` copies. Reverting the `is-accessor-descriptor` copy → vex `not_affected`. Reverting the `is-number` copy → `not_applied`. Same crawl-order dependence. It's likely the same for yarn classic, bun hoisted and pnpm (multiple `.pnpm` peer variants of one version).

Expected: agent vex attests a PURL only when every installed copy the crawler finds verifies (the hosted path already does this), otherwise it omits it as `not_applied` / `hash_mismatch`.
