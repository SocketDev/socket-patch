**Ruled out (not filed):**
- `npm dedupe` drops a pin only when the patched name is duplicated in the tree, because npm then re-resolves it like `npm update <name>`. `vex` and `vendor --check` fail closed afterwards. This is npm behaviour.
- Vendored `vex` over a stale tree attests with a `vendored_tree_out_of_sync` warning, as documented in CLI_CONTRACT.md.
- A root-level extraneous copy (`npm install --no-save`) makes vendored `scan` exit 1 with no in-run VEX on every run (hosted only warns). The suggested `npm install` prunes the copy and clears it, so this is a parity question, not a broken refusal. Recorded under Known non-bugs.
- Hosted `rollback`'s "the registry records no integrity" refusal can't be reached on npmjs: even 2014-era versions now carry a sha512 `dist.integrity`.
