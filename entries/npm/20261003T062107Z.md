## Cells (Linux)
- **npm 6 v1 lock, hosted → vendored takeover via `scan`/`get --mode vendored`: fail #659 (new).** The takeover restores the hosted pin to upstream and deletes `.npmrc`, then the v1 gate refuses (`vendor_lockfile_version_unsupported`). The patch is lost: exit 1, but nothing is rolled back, and `npm ci` installs upstream bytes. The `npm-shrinkwrap.json` v1 variant behaves the same. The dry run exits 0 with no preview. `vendor` (eject) on the same project rolls back correctly (`eject_rolled_back`). v4.0.0 does the same, so it isn't a regression.
- Hosted cycle over rich lock entries (npm 10, v3): `semver` (bin, engines, transitive `lru-cache`), `rimraf@3` (deprecated, funding), devDep, optionalDep, peerDep, all patched at once. Fresh `npm ci` gives all 6 patched, `vex` covers 6 subcomponents, and `rollback` is byte-exact. Pass.
- `.npmrc` ownership (npm 10): a user `allow-remote=all` line is kept through scan / partial `remove` / `rollback`, byte-exact. If hosted appended the line to an existing `.npmrc`, the line is kept after `rollback`. That's documented (`npm_allow_remote_left`), so it's a known non-bug.
- Agent crawl of packages named after skip-list dirs (`tmp`, `temp`) with nested `node_modules` (`tmp/node_modules/os-tmpdir`, `temp/node_modules/rimraf`): 4/4 patched. Pass.
- Lockfile-only discovery on a **v1** lock (npm 6, no `node_modules`): `scan` in any mode finds 0 packages and prints "No packages found. Run your package manager's install first." (exit 0). A v2 lock finds them (`lockfileOnlyPackages: 2`). `list` / `vex` / `rollback` read v1 hosted pins fine. The code says this is "documented" (`lock_inventory/npm.rs:168`), but neither CLI_CONTRACT's "Lockfile supplement" nor npm-compatibility.md mentions it. The message is loud and installing first works around it, so it's not filed. Added to known non-bugs as an undocumented limitation.
