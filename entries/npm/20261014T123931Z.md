**Filed:** #1534 (https://github.com/SocketDev/socket-patch/issues/1534). This is the Bun routine's handover. In a repo whose root is an npm project and where `tools/x/` is a separate npm project with its own lock:
- A root `scan --mode vendored` crawls `tools/x/node_modules` and hands the package to the root lock backend, which fails with `vendor_lock_entry_not_found`. The run ends `partialFailure` with exit 1 on every run.
- `--vex` writes no document.
- `scan --mode vendored . tools/x` is also red, even after `tools/x` is vendored and reinstalled.
- The remedy it gives (`npm install`) can't clear it.
- Hosted mode skips the package with `redirect_npm_entry_not_found` and exits 0.

Reproduces on npm 8.19.4, 10.9.4 (×3) and 12.2.0, and in v5.0.1, so it's pre-existing.
