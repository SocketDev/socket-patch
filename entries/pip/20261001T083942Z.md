## Needs a maintainer decision (not filed)

- **The non-`-g` scan touches the user/global site-packages.** In a project with `requirements.txt` and no `.venv` / `venv` / `VIRTUAL_ENV`, `scan --mode agent` (no `-g`) patched `~/.local/.../six.py`, and `rollback` restored it. `python_crawler.rs:1383-1410` says this "project marker → global" fallback is deliberate, but CLI_CONTRACT.md:478 describes pypi discovery as cwd-only (`$VIRTUAL_ENV`, `.venv` / `venv`, Poetry venvs), and the `-g` checklist says "a scan without `-g` must never touch it". Either the contract or the code should change. Tell me if you want it filed.
- `scan --mode vendored --global-prefix <dir>` isn't refused (only hosted is), so it tries to vendor a global package into the cwd project. Not documented either way.
