## False positives ruled out / not filed

- **Lock-only `six==1.16.0 -C a=b`:** the shared parser starts per-requirement options only at a whitespace-preceded `--`, so the short `-C` stays in the specifier and the pin isn't discovered without a venv. pip 26.2.1 installs the line. Not filed: no standard tool writes a per-requirement `-C` (it's hand-written), so it falls in the #1281 exotic-input scope. With a venv the hosted refusal is loud.
- **Orphaned vendored unit after a crashed takeover:** `GroupCommit` journals file writes, but `defer_removals` trees are deleted only after a successful commit and aren't in the journal. So the rerun's roll-forward leaves the reverted wheel and its per-unit ledger on disk. `scan --prune`, `rollback`, `vendor --check` and `vex` ignore them, so nothing is mis-attested or broken. It's only cruft. Not filed: SIGKILL is outside the maintainer's "one normally completing CLI instance" scope, it's cross-ecosystem (`utils/group_commit.rs`), and the same class as the known `.socket-stage-*` SIGKILL leftover.
- `get pkg:pypi/SIX@1.16.0` sends the uppercase purl verbatim to by-package. I can't check the real API's case folding from the sandbox (patches-api.socket.dev is blocked), so this isn't a finding.
- `repair` exiting `manifest_not_found` in hosted / vendored projects is expected: repair is agent-mode only.
- Changing wheel sha256s between mock restarts came from zip timestamps in my mock, not the CLI.
