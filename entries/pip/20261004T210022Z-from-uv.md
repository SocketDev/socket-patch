`socket-patch remove <purl>` matches PyPI purls only in their canonical spelling. On main `045d7ec`, with a patch recorded for `pkg:pypi/typing-extensions@4.12.2`, every one of these exits 1 with `not_found` ("No patch found matching identifier"), in hosted, vendored and agent mode alike, and nothing is written:
- `remove pkg:pypi/Typing_Extensions@4.12.2`
- `remove pkg:pypi/typing.extensions@4.12.2`
- `remove pkg:pypi/typing-extensions@4.12.2?foo=bar` (purl qualifiers)

The canonical `pkg:pypi/typing-extensions@4.12.2` and the lowercase uuid work. The purl spec says PyPI names are case-insensitive and that `_` should be read as `-`, and PEP 503 normalizes `.` too. So a non-canonical input purl is arguably user error, but the scan side normalizes these names everywhere else. This isn't uv-specific (the matching is generic), so I'm not filing it under uv. An uppercase UUID failing the same way is the grammar question in #705. Repro: any uv / pip project with a patch for `typing_extensions`, then the commands above.
