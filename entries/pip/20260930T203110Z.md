## False positives ruled out

- `vendor_fetch_failed` against pypi.org is the sandbox TLS artifact; not needed here.
- The `uv pip install` of the hosted URL failed on my mock (501 on HEAD). That's a mock artifact, not a bug.
- `six==1.16` / `six==1.16.0.0` scan outcomes depend on my mock's string-matched batch endpoint, so they weren't judged.
- Lock-only discovery ignores `six == 1.16.0` (spaces) and `six===1.16.0`, while the hosted rewriter accepts both. `utils/requirements.rs` tests this on purpose (`exact_pin("six == 1.0") == None`), so it's a design choice; it goes in the backlog, not filed.
- Probe run 36771795909's "latest" cells used setup-python's bundled pip (26.2.1 on 3.13, 23.x / 25.x on 3.8) because of a probe-script glitch. Every cell still exercised a real pip.
