## Issues

- Filed #638: https://github.com/SocketDev/socket-patch/issues/638. Hosted `--json` reports `success` with empty `skipped` and `warnings` when a PyPI project has no root `requirements.txt`. Human output names the package, but no `redirect_pypi_no_lockfile`-style code is emitted, unlike npm, pnpm, vlt, composer, gem, maven and go. Same on v4.0.0, so not a regression.

## False positives and limits ruled out

- `record_fetch_failed` in the first sweep was a mock artifact (no `view` route); it was gone once the route was added.
- Rollback rewrites an unpinned hosted `six` back as `six==1.16.0` (and `===` as `==`). Hosted mode is stateless, so the restore derives the line from the hosted URL by design. Not filed; added to the maintainer questions below. It matters most with `-c constraints.txt` workflows, where a later constraint bump then conflicts with the new root pin.
- The vendored `-c` refusal says "six is not pinned to ==1.16.0" even though the constraint pins it. The wording is imprecise but the behaviour is fail-closed.
