## Ruled out / not filed
- `six===1.16.0`, `six (==1.16.0)`, `six==1.16.0.0`, `six==01.16.0`, `six==v1.16.0`: refused in both modes with `*_hatch_unsupported` "requires an exact ==1.16.0 declaration" (hosted exits 0 with a warning, vendored exits 1). It's an over-refusal that fails closed, the same class as the logged `six==1.16`.
- Hosted rollback removing a pre-existing `allow-direct-references = true/false` (and an emptied `[tool.hatch.metadata]` / `[metadata]` table, which leaves a 0-byte hatch.toml). `drop_direct_reference_permission` (`patch/redirect/upstream/pypi.rs:785`) can't tell a user-set value from its own because v5 hosted has no ledger. A false value is also overwritten at scan time. There's no functional effect: the line is only dropped when no other direct reference remains, and false is Hatch's default. Logged as low severity rather than filed. Unlike the uv #411, it changes no resolution.
- Vendored `pypi_hatch_unsupported` "require Hatch >=1.2 on PATH": a harness artifact (Hatch invoked by absolute path). Documented preflight.
