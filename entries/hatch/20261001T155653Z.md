## Filed
- #479: **Hatch 1.17+ environment locks.** `hatch lock` (new in 1.17.0, with `locked = true` / `lock-envs`) writes a `pylock.toml` / `pylock.<env>.toml` that is derived from pyproject. When one exists, hosted and vendored scans rewrite only the pylock and report `success`. The existing env stays unpatched (the dependency hash is unchanged). A fresh env regenerates the lock from pyproject, which wipes the wiring and installs upstream six. `hatch dep lock --check` exits 1. Vendored also skips the documented uv-installer refusal. The same happens with an exported pylock on a non-locked env. Control: with no committed pylock, the pyproject rewrite passes through Hatch's re-lock (fresh env patched, `--check` 0). Suspect: the early return in `rewrite_hatch` (`redirect/mod.rs:686-695`). Fails on Linux, macOS and Windows × 1.17.0 / 1.18.1 × hosted and vendored. Probe: https://github.com/SocketDev/socket-patch/actions/runs/36887192239
