## False positives ruled out
- Pipenv refuses different versions of one package across `[packages]` and a named category (it constrains categories by default), so a "per-category version mismatch" shape can't happen.
- `vex` exits `product_undetected` on a bare Pipfile project: a Pipfile has no name or version, and `--product` is the documented remedy.
- Hosted rollback "error sending request" against pypi.org: the known rustls-vs-proxy-CA sandbox artifact. It passes through a `SOCKET_PYPI_JSON_API` forwarder.
- Old Pipenv + `virtualenv<20` can't copy uv's standalone CPython (`libpython3.8.so` missing): a sandbox/tooling artifact; use virtualenv 20.x.
