**v5 harness note:** hosted pins are recognised only on the named patch server, so set `SOCKET_PATCH_SERVER_URL=<mock>`. Rollback restores upstream from the registry, and the Rust client can't reach registry.npmjs.org from the sandbox, so set `SOCKET_NPM_REGISTRY=<mock>/registry`. Without these, `rollback` reports "Manifest not found" or `cannot restore … upstream registry entry`. Both are fixture artifacts.

### False positives ruled out
- "rollback deletes the user's pnpm-workspace.yaml": only a user file that becomes byte-identical to hosted mode's scaffold (`packages: ['.']` plus the appended `trustLockfile: true`) is deleted. That's documented in CLI_CONTRACT.md (upstream restore, npm family).
- `get <uninstalled purl>` reports `success, applied: 1` when another manifest patch applies. The nested apply fails only when *no* entry matches. It's not pnpm-specific, so it wasn't filed; it's noted on #362.
- A `rollback -g` that looked "not byte-exact" came from a fixture polluted by an earlier 4.0.0 `scan` in the same global dir. Clean re-runs are byte-exact.
