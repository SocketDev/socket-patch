Transitive deps installed in `common/temp/node_modules/.pnpm` therefore show as `notInstalled`. After `scan --mode hosted` pins `common/config/rush/pnpm-lock.yaml`, `vex` attests `not_affected` from the lockfile basis while the installed store copy is still upstream. On plain pnpm in the same state, `vex` correctly says `not_applied`. Agent `apply` for the same transitive dep reports `package_not_installed`. Direct deps pass. Reproduced 2/2. https://github.com/SocketDev/socket-patch/issues/518
- pass: hosted on Rush. `scan --mode hosted` pins the Rush lock with `redirect_rush_repo_state_stale`. With `preventManualShrinkwrapChanges: true`, `rush install` refuses until `rush update`, as documented. The pin survives `rush update`. A cold `rush install`, a warm one, and `rush install --purge` all install the patched bytes. `vex` attests correctly once the tree is patched.

Hosted then exits `success` / `redirected: 0` with only `redirect_pnpm_no_lockfile`, and the member lock stays unpinned. Reproduced 2/2. https://github.com/SocketDev/socket-patch/issues/492#issuecomment-5943308968
