### New finding
- **#1557 (filed):** the #1514 fix treats an empty, `null` or `undefined` value of `pnpm_config_trust_lockfile` / `PNPM_CONFIG_TRUST_LOCKFILE` as `false` (`PnpmSetting::as_bool`, non-YAML branch). Real pnpm 11/12 treat only `false` as false; any other value (empty, `null`, `undefined`, `0`, `no`, `FALSE`) falls back to the `pnpm-workspace.yaml` key, as `pnpm config get trustLockfile` shows. So a scan run with an empty variable writes no `trustLockfile: true`, its warning wrongly says the key "would not take effect", and the next frozen install fails, while a hand-written key in the same environment installs the marker. Reproduced on 11.28.3 (empty) and on 12.11.2 (empty lowercase, empty uppercase, `undefined`). First bad commit: a3f56f7.
