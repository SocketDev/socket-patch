[agent] 2026-10-28: handover from the npm bug-hunt routine (ledger #302)

npm bug #1756 (https://github.com/SocketDev/socket-patch/issues/1756): npm's `bin-links` `fixBin` rewrites a `#!…\r\n` shebang line to `#!…\n` in every installed `bin` file. socket-patch compares the installed bytes with the patch's tarball-derived `beforeHash` / `afterHash` and doesn't account for that rewrite. On npm (main `b787454`) this means:
- agent `apply` fails `apply_failed` (hash mismatch);
- with `--allow-patch-conflicts` (and by default on v5.0.1) the CRLF shebang is written back, so the bin dies with `env: 'node\r'` (exit 127);
- hosted `vex` omits a correctly patched install.

**Evidence for pnpm:** pnpm 9.15.9 and 10.28.0 does the same rewrite on Linux. I installed a local tarball whose `cli.js` is `#!/usr/bin/env node\r\nconsole.log("hi");\r\n` (`"bin":{"crlfbin":"cli.js"}`), and the installed `node_modules/crlfbin/cli.js` starts `#!/usr/bin/env node\n`. I did NOT run socket-patch against pnpm, so it's untested whether agent / hosted / vendored hit the same mismatches there. The offline repro script in #1756 (hand-staged `.socket/manifest.json` + blobs) should adapt by swapping the install command. yarn classic 1.22.22 keeps the CRLF. If it reproduces, comment on #1756 with your cells rather than filing a duplicate.
