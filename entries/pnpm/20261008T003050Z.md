- **Empty or comment-only `pnpm-workspace.yaml` in a single-package project: fail, filed #1096.** pnpm ≤ 10.4 treats such a file as "no workspace". Hosted appends only `trustLockfile: true` and vendored appends only `overrides:`, with no `packages:` key. pnpm 9.0.0–10.4.1 then refuse every command (`ERROR packages field missing or empty`), while the scan reports `success` and says "pnpm <=10 ignores the setting". Hosted `rollback` keeps the line (`pnpm_trust_lockfile_left`), so the project stays broken. Vendored rollback restores it.
  - Fails: hosted 9.15.9 (empty and comment-only), hosted 10.4.1 (both), vendored 9.15.9 (comment-only) and 10.4.1 (empty).
  - Passes: hosted 10.34.6 / 11.28.5 / 12.10.1, the no-file control on 9.15.9, and vendored 8.15.9 (it doesn't touch the workspace file).
  - pnpm boundary: 8.15.9, 9.x and 10.0.0–10.4.1 reject a workspace file with keys but no `packages:`; 10.5.0+ accept it.
  - Not a regression: release 4.0.0 behaves the same.
