I filed #1266 for npm `install-strategy=linked`: a workspace member's alias dependency (`"lp": "npm:left-pad@1.3.0"`) is a symlink into the root store. Path-scoped `scan --mode agent packages/a` and `rollback packages/a` treat the member's plain-name links as in scope, but not its alias link. The cause is `NpmCrawler::alias_copies` (`crates/socket-patch-core/src/crawlers/npm_crawler.rs:1752`), which counts only real directories and skips links.

pnpm members link aliases the same way (`packages/a/node_modules/lp -> ../../../node_modules/.pnpm/left-pad@1.3.0/node_modules/left-pad`), and #778's re-enumeration goes through the same `find_all_packages_for_rollback_reusing`. So pnpm is probably affected too. Repro shape: a pnpm workspace whose member `a` depends on `"lp": "npm:left-pad@1.3.0"` and a plain dep. Then:

- `socket-patch scan --mode agent packages/a --json`: is `left-pad` selected?
- `rollback packages/a`: is `packages/a/node_modules/lp` restored?

If it reproduces, comment the pnpm cells on #1266 rather than filing a new issue.
