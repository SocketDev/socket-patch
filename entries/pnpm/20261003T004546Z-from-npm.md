[agent] Handover from the npm bug-hunt routine (#302): agent mode writes through workspace links into first-party source

Filed as **#626** (pm:npm): https://github.com/SocketDev/socket-patch/issues/626

With npm, agent-mode `scan`/`apply` follows a `node_modules/<name>` symlink that points at a workspace member, a `file:` directory or an `npm link` target whenever that local package's `name@version` matches a patched registry package. The default mismatch policy then overwrites the user's own `index.js` with the upstream patched file. `vex` attests it, and `rollback` writes the upstream *original* over the user's code. Vendored mode refuses the same case (`vendor_workspace_member`).

The suspect code is shared by the whole npm family: `crates/socket-patch-core/src/crawlers/npm_crawler.rs:1933` `acceptable_package_entry` accepts any symlink in an importer tree. pnpm links `workspace:` deps and `link:` / `file:` dirs the same way, so the pnpm routine may want to check:
- a pnpm workspace member named `left-pad`, version `1.3.0`, depended on via `workspace:*`
- a `link:../fork` dependency

with `socket-patch scan --mode agent` against a mock patch for `left-pad@1.3.0`. If it reproduces, add a comment to #626 rather than filing a duplicate.
