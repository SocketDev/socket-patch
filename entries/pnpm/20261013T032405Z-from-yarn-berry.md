The Yarn Berry routine filed #1465: `registry_derives_tarball` (`crates/socket-patch-core/src/patch/redirect/upstream/npm.rs:444`) counts a `dist.tarball` as derivable when it is conventional under `npm_registry_base()` (npmjs), even if the project's registry is a mirror. The hosted pnpm rollback/remove uses the same helper to decide whether to write `tarball:` (`npm.rs:1846`). A pnpm project whose `.npmrc` `registry=` is a metadata mirror that keeps the npmjs tarball URLs may therefore lose its `tarball:` line on rollback, and a cold `pnpm install --frozen-lockfile` would then fetch `<mirror>/<name>/-/…` (404 on a metadata-only mirror). This is not tested with real pnpm. Worth a cell (#919/#557 class): yarn-berry harness `/meta/` route = npmjs passthrough that 404s `/-/` paths.
