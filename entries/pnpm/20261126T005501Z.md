### Issues
- Filed **#2263** (https://github.com/SocketDev/socket-patch/issues/2263). On pnpm 12.23.0, a project with hosted patch B (`peer-user`) and vendored patch A (`leaf`, a dependency of `peer-user`) fails every install with `ERR_PNPM_LOCAL_SUBDEP_NOT_ALLOWED` ("a non-local package snapshot references an unauthorized local filesystem dependency"). Both `get` commands exit 0, in either order, and a plain `pnpm install` fails too.
  - Passes on 11.20.0, 11.29.0, 12.0.0, 12.21.0 and 12.22.0.
  - v5.1.0 (trustLockfile pin) fails the same way on 12.23.0, so it's a new pnpm check, not a socket-patch regression.
  - The hosted → vendored takeover reaches the same lock when the peer-suffixed hosted package can't be vendored.
- Filed **#2264** (https://github.com/SocketDev/socket-patch/issues/2264). A `catalog:` importer dependency makes the scan fall back to whole-lock `trustLockfile`, and the warning says "pnpm would not override" it. But pnpm 11.29.0 / 12.23.0 do route a catalog dependency through the hand-written override: the dependency leaves `catalogs:`, its specifier becomes `socket-<id>:1.0.0`, a fresh frozen install is patched and `dedupe` is stable. Reproduced 3×.

### False positives ruled out
- pnpm 12 returned 405 for a localhost registry: the sandbox proxy, because pnpm 12 ignores `NO_PROXY` while `npm_config_https_proxy` is set. Stripping the proxy variables fixed it.
- Hosted `rollback` printed `manifest_not_found` and `vex` printed "No patches" / `record_unavailable`: `SOCKET_PATCH_SERVER_URL` and `--api-url` weren't set for the mock. Documented.
- `pnpm update` exit 1 on 12.23.0: pnpm asks the mock registry for `/pnpm`. Mock gap.
- `redirect_grant_malformed`: my mock's integrity lacked the `sha512-` prefix.
