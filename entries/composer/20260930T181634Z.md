[agent] 2026-09-30: Composer bug-hunt run

This is the first run, so the ledger started empty and there were no `pm:composer` issues to re-triage.

**Tested:** main `f6b7fb9` (CLI 4.0.0 = latest release). Composer 2.8.12 on PHP 8.4.19, Linux only. No probe branches this run: both defects are OS-independent file/text logic.

## Cells

- **Agent, `setup` on a CRLF composer.json:** **fail → #351.** `setup` rewrites the whole file as LF, and `setup --remove` doesn't restore the CRLF bytes (CLI_CONTRACT §8). The same serde round trip also un-escapes `\/` and `\uXXXX`. Composer's own `composer config` keeps CRLF.
- **Agent, `setup` + real `composer install` / `install --no-dev`:** pass. The hook runs `socket-patch apply --offline --silent --ecosystems composer` with exit 0 and leaves no `.socket/` residue when there's no manifest.
- **Agent, BOM composer.json:** not a bug. Composer itself rejects it ("does not contain valid JSON").
- **Scan, custom `config.vendor-dir: lib/deps`** (plus `COMPOSER_VENDOR_DIR`) with `require-dev`: pass (2 packages discovered).
- **Vendored, installed from source** (`--prefer-source` / `preferred-install: source`) **→ git commit → fresh clone → `composer install`:** **fail → #355.** The copy carries `.git/`, git records a gitlink to the pristine upstream commit, and the fresh clone installs an empty package with exit 0. VEX correctly refuses on the fresh clone.
- **Repo capstones** (`e2e_redirect_composer_build`, `e2e_vendor_composer_build`) on 2.8.12 / PHP 8.4: hosted 5/5 pass. Vendored 4/6 pass. The 2 failures (`…mirror_filters_would_drop`, `…fast_path_heals_legacy_copy`) are the same `.git` copy as #355: the sandbox can't download GitHub zipballs, so Composer falls back to source.

## False positives ruled out

- A BOM composer.json is rejected by Composer itself, so socket-patch's refusal matches.
- `vendor/`-style `.gitignore` patterns also match `.socket/vendor/`. That was my own repro bug; use `/vendor/`.
- The sandbox always installs from source (zipball downloads fail), so a local "dist" control isn't possible. Upstream CI is the dist control.
