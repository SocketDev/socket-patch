## Cells

- **Hosted, a package from a Composer repo that has `options.http.header`:** **fail → #399** (filed). Composer copies repo `options` into the lock as `transport-options`. The hosted rewrite keeps them, so `composer install` sends the private header to the hosted patch URL. Reproduced on 1.10.28, 2.2.30 and 2.8.12 (twice).
- **Hosted, warm Composer cache from the pristine install** (dist keeps `reference`): pass on 1.10.28 / 2.2.30 / 2.8.12. Composer re-downloads, and the patched bytes install.
- **Hosted → vendored takeover** (`scan --mode vendored --vendor-source build` over a hosted lock): pass.
- **Vendored, source-only lock entry** (a `type: vcs` repo with no dist): **fail, same bug as #355.** No `--prefer-source` is needed. The probe shows it fails on all 9 OS × version cells: the gitlink is committed, and the fresh clone's `composer install` exits 0 without the patched package. I added two comments to #355.
- **Vendored, path repo `symlink: false` → fresh install → `vendor --revert`:** pass on all 9 probe cells, plus locally on Composer 1.10.28.
- **Vendored, path repo (default symlink), transport-options `{relative: true}` → revert:** the lock is restored byte for byte. Pass.
- **Vendored, `dev-main` version → fresh install → `repair` (copy deleted) → `remove <purl>`:** pass. The lock is restored, including `transport-options`.
- **Vendored, `dev-feature/foo` (slash in the version):** refused with `unsafe_coordinates`, fail-closed. Agent mode applies fine. Not filed (see below).
- **Agent apply, Composer 1.10.28 installed.json (no `install-path`):** pass.
- **Agent apply, path-repo package installed as a symlink/junction:** writes through the link into `../sib`, outside the project. Same in all 9 probe cells. Not filed (see below).
- **`setup --check` with the hook in only one of `post-install-cmd` / `post-update-cmd`:** it reports `configured` (exit 0) while `setup --dry-run` reports `wouldUpdate: 1`, and a fresh `composer install` leaves the package unpatched. Confirmed twice. **Not filed:** `setup` is deleted on `release/v5-prerelease` (#279, merged), so a fix is unlikely to be worth it. Recorded below.

## False positives ruled out

- A `"packages-dev": null` lock: Composer 2.8 itself fails to install from it (`Locker.php`), with or without socket-patch. Not a socket-patch bug.
- Path-repo symlink write-through: the npm crawler deliberately accepts `npm link` / `file:` symlinks too, and Composer created the link from the user's own composer.json. It's a design question, not a contract violation.
- `unsafe_coordinates` for a `/` in a dev branch version: an explicit fail-closed refusal on a shape Socket patches don't target (released versions).
