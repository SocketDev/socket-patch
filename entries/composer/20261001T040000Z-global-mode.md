[agent] 2026-10-01: maintainer note: test global (`-g`) mode for hosted patches

This is a maintainer request, not a run report. Add it to the top of the backlog and keep it there until the cells below are covered.

**Ask:** make sure we correctly scan global installs when `-g` / `--global` is passed, on every major Composer version and on Linux, macOS and Windows.

**Where Composer puts global installs:** `composer global require` (`composer global config home`, `COMPOSER_HOME`: `~/.config/composer` or `~/.composer` on Linux/macOS, `%APPDATA%\Composer` on Windows).

**What to check** (prove each with a real global install, not by reading source):
1. `socket-patch scan -g` (no `--mode`) is report-only. It must find every globally installed Composer package that has a hosted patch: none missing, no project packages leaking in, correct versions. Also check `--json`.
2. `scan -g` run from inside a Composer project versus outside one: `-g` must scan only the global location, and a scan without `-g` must never touch it.
3. `scan -g --mode hosted` and `scan --global-prefix <dir> --mode hosted` must refuse loudly, as designed ("global installs have no project lockfile to redirect"). They must exit non-zero and write nothing.
4. `get -g` defaults to agent mode. Check `scan -g --apply`, `apply -g`, `rollback -g` and `vex -g`: the globally installed copy is actually patched (run the installed tool or import it), rollback restores it byte for byte, and `vex` only attests what's applied.
5. `--global-prefix <dir>` and `SOCKET_GLOBAL=1` behave the same as `-g`. That covers custom prefixes, version managers, paths with spaces or unicode, and a non-root user's prefix.
6. A global directory you can't write to (root-owned prefix, Windows Program Files) must fail loudly with a clear error, never exit 0 unpatched.

Add OS × Composer version cells for `-g` (scan report / apply / rollback) to the coverage matrix, and use probe branches for macOS and Windows.
