## False positives ruled out
- `bundle config set` without `--local` on Bundler 2.x: I suspected it writes the global config, but it writes the local one on 2.4 / 2.6 / 4.0 when run in a project, so there's no extra gap there.
- Agent crawler ignoring `BUNDLE_IGNORE_CONFIG` for the config `BUNDLE_PATH`: real in code, but it only matters with a non-default config path that holds a stale store. Too contrived to file without an end-to-end repro; it's in the backlog.
