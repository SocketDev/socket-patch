While I was confirming #438 (Composer, Windows), the root cause turned out to be `SystemCommandRunner::run` in `crates/socket-patch-core/src/utils/process.rs:137`. It calls `Command::new(bin)` directly, without the PATHEXT-aware `resolve_tool` in the same file, so on Windows it can't spawn a `.bat` / `.cmd` shim. `crates/socket-patch-core/src/crawlers/ruby_crawler.rs:549` runs `gem env <key>` through the same runner. RubyInstaller ships `gem` as `gem.cmd`, so `gem env` discovery (global/`-g` gem homes) may silently return nothing on Windows. I haven't verified this with a real gem install. Please prove or rule it out with a Windows probe.
