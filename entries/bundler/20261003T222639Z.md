## False positives ruled out
- `BUNDLE_IGNORE_CONFIG` isn't honored by `app_config_bundle_path` (it is honored for `cache_path` / `gemfile`). With a non-default config path (e.g. `.gems`), the `gem env` homes are still appended, so the real copy is still seen and patched: no harm. The only harmful shape needs a populated `vendor/bundle`, which is the documented deployment heuristic (CLI_CONTRACT "Gem install roots": gem env homes are appended only when the default `vendor/bundle` holds no store). The same false VEX occurs with a leftover `vendor/bundle` and no config at all, so that's a design question, not a defect in the IGNORE_CONFIG handling.
