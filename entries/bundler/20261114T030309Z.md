**Ruled out**
- `vex` from a monorepo root attests only the root project while scan, `list` and `rollback` cover the directories below: documented ("`vex`, `apply`, `repair`, `remove` and `rollback <target>` act on the one project at `--cwd`").
- `remove rack` from a monorepo root where only the sub-projects pin rack: "No patch found matching identifier", exit 1. Same rule; the message doesn't name the directories below, which the contract promises only when `--cwd` holds no patch state at all.
- `vex --json` without `--output` is an error (`json_requires_output`): documented.
