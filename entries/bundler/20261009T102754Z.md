## Issues
- Filed #1260: https://github.com/SocketDev/socket-patch/issues/1260. Hosted gem `rollback` / `remove` leave the patched `.gem` in `vendor/cache` (or `cache_path`), so every later `bundle install` exits 37 (mismatched checksums) while the unwind reports success with only `reinstall_required`. On Bundler 2.5, frozen installs keep the patched gem. Control: deleting the archive makes the install pass.

## False positives ruled out
- The lockless capped scan appended `rainbow`, which the project never declared. My mock's `/patches/batch` offers every gem regardless of the query. Not filed. The real behaviour is #1125's shared-home crawl.
- The first in-run `--vex` probe exited 1 with `redirect_gem_stale_install`, because the project had pre-installed unpatched copies in `vendor/bundle`. That's the documented guard. Lock-only it passes.
- Harness pitfall hit again: `ps … | grep "[m]ock.py"` + `kill` in the same command killed the shell (exit 144). Kill the PID in a separate command.
