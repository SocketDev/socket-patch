## Filed / commented
- **#477** (new): after a hosted **or** vendored rollback, `pdm sync`, `pdm install` and `pdm install --frozen-lockfile` keep the **patched** build installed (`All complete! 0/0`; `direct_url.json` still points at the patch server, or at the deleted `.socket/vendor` wheel). Rollback's note says the bytes stay "until the next package-manager install", which is false on PDM. Only `pdm sync --reinstall` restores upstream. Reproduced on 1.4.5, 2.12.4 and 2.29.2, vendored and hosted.
- **#332** commented: global mode hits it too. With PDM 2.12.4 `install.cache` + symlink, `pdm add -g` links the global interpreter's `urllib3` directory into the cache. `scan -g --mode agent` then patches PDM's cache and, through it, a never-scanned project (2/2 runs). `rollback -g` un-patches both. The 2.29.2 control is clean.
- **#424** commented (Maven-labelled, generic): the same `scan --json` agent-apply failure drop reproduces for PyPI. A root-owned `--global-prefix`, run as uid 65534, gives exit 1 with `failed: 0` and no error, while `apply --json` gives `apply_failed` / "Permission denied".

## Ruled out / not filed
- Rollback deletes the manifest entry, so a later `apply` has nothing to do. That's documented (usage.md: rollback "remove[s] their local state").
- A mode-less `scan` (not `-g`) defaults to **hosted** and rewrites the lock. That's documented. My own run tripped on it mid-test; the affected observation was discarded and redone.
- `vex` needs `--product` outside a packaged project (documented error).
