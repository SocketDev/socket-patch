### Cells (Linux)
- **vlt's workspace-glob dialect, probed with real `vlt install`** (1.3.8): vlt lists members for `packages/{a,b}`, `packages/**`, `packages/[ab]`, `packages/?`, `packages/+(a|b)`, `packages/@(a|b)`, `./packages/b`, `packages/b/` and `packages/b/**`. A `!` pattern excludes regardless of order (`["!packages/a","packages/*"]` drops `a`), but a later literal path re-includes (`["packages/*","!packages/b","packages/b"]` keeps `b`). `"packages"` lists nothing.
- **#1134 shape (stray member `vlt-lock.json`) × glob syntax:** `packages/*`, `{a,b}`, `**`, `[ab]` and an object group refuse in both hosted and vendored, and write nothing: **pass** (1.2.0 / 1.3.8). Extglob `+(a|b)` / `@(a|b)`: **fail #1542**. Hosted and vendored both exit 0 and write the member's lock or `package.json`; `vlt ci` then installs pristine (vendored: `vlt ci` fails "out of sync"); vendored `vex` attests `not_affected` (1.2.0 / 1.3.8, `vlt.json` and `package.json` workspaces).
- **Excluded-by-`!` directory** (`["!packages/a","packages/*"]`): `vlt install` run inside `packages/a` installs the root project, so `a` is never its own project. socket-patch counts `a` as a member (last-match-wins) and refuses, which is fail-closed. I noted it in #1542 as a dialect mismatch, not a separate bug.
