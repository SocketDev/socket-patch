A standalone mock of the patch API and patch registry works for all three modes (endpoints: `POST …/patches/batch`, `GET …/patches/by-package/<purl>`, `POST …/patches/package`, `GET …/patches/view/<uuid>` with `blobContent`, and a compact index under `/patch-registry/gem/<token>/<uuid>/`; copy the `/info` line from rubygems.org and swap the checksum). Build the patched gem by repacking the upstream `.gem` with its `metadata.gz` unchanged, and pass `--api-url <mock> --proxy-url <mock> --patch-server-url <mock>` to every command (without a token the CLI calls the proxy URL). For vendored mode the grant's `tarball` artifact needs `integrity.sha512` (SRI) and a second artifact `{"kind":"gem-stub-gemspec"}` serving `gem spec <patched.gem> --ruby`. Select a Bundler with `BUNDLER_VERSION`. A patched gem needs no Ruby: change one file in `data.tar.gz` and recompute `checksums.yaml.gz`. A realistic project: `gem install rails -v 7.1.5` into a scratch `GEM_HOME`, then `rails new app --skip-git --skip-bundle --skip-javascript --skip-hotwire --skip-asset-pipeline --skip-docker` (81 gems); patch rack, puma, bootsnap, web-console, capybara. Agent mode needs no mock at all: write `.socket/manifest.json` and `.socket/blobs/<git-sha256>` by hand, with the gem's own file as `beforeHash`. Kill an `apply` with `timeout -s KILL`. `scan --mode agent` works through the mock when the view's files carry `blobContent` / `beforeBlobContent` (base64). A C marker with no `Init_` edit: append `__attribute__((constructor)) static void m(void){ rb_define_global_const("X", Qtrue); }`. Rails 8: `gem install rails -v 8.0.2`, same flags. For a superseding patch, restart the mock on the same port with a new uuid for the purl. `vex` writes with `--output` (`-o` is `--org`); `remove` takes one purl. ## Known non-bugs

The full list is in `known-non-bugs/bundler.md` on this branch. Search it with `git grep` before filing, and append one line when you rule something out. Don't read it whole. Most likely to be re-filed:

- "the patched gem's gemspec differs from the installed one" after a hosted scan: a mock gem rebuilt with `gem build` has a different gemspec. Repack with the original `metadata.gz`.
- `vex` / `list` report no patches on a hosted project whose patch URLs are on loopback: pass `--patch-server-url`.
- `vex` exits 2 asking for a product when the project has no git origin, gemspec or other manifest: pass `--product`.
- Hosted scan leaves gems in a shared gem home unpatched and warns: documented ("Ruby gems: gems already installed").
- `apply --check` says a native gem is out of sync after Bundler rebuilt it from the hosted patched gem (agent record + hosted pin): documented, run `apply` again after a reinstall.
