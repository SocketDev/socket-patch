Harness notes: the sandbox reaches rubygems.org but not the Socket patch API. Use the repo's own stand-in, `tests/nokogiri/patch_service.rb`: `PatchService.new(name, version, platforms, uuid, ghsa, workdir, mark)` downloads the real gems, appends `mark` to `lib/<name>.rb`, and serves the patches API, the compact index and the artifacts for ONE gem on a loopback port (org `nokogiri-e2e`). An empty platform list gives a ruby-platform patch; vendored mode then also needs a `gem-stub-gemspec` artifact (add it to `package_result` and serve the gem's `spec.to_ruby`). For several gems, a superseding patch or agent mode, put one loopback server in front of several instances: override each one's `url` with the front's, send a path that holds a uuid to that instance's `respond`, merge `batch` and `package`, and serve `/patches/blob/<git-sha256>` from its `@before` / `@after`. Pass `--api-url <mock> --patch-server-url <mock> --api-token fake --org nokogiri-e2e` to every command. Git-ignore `**/vendor/bundle/` in test repos. Rubies are in `/opt/rbenv/versions` (3.1.6: Bundler 2.3.27, 2.6.9; 3.2.6: 2.4.19, 4.0.18; 3.3.6: 2.5.22, 4.0.18, 4.1.0); `gem install bundler -v <v>` works. Select a Bundler with `BUNDLER_VERSION`. A realistic project: `gem install rails -v 8.0.2` into a scratch `GEM_HOME`, then `rails new app --skip-git --skip-bundle --skip-javascript --skip-hotwire --skip-docker`. A release build takes over 10 minutes. `vex` writes with `--output` (`-o` is `--org`); `remove` takes one purl. No Ruby 3.4 / 4.0 here (ruby-build's downloads are blocked).

## Known non-bugs

The full list is in `known-non-bugs/bundler.md` on this branch. Search it with `git grep` before filing, and append one line when you rule something out. Don't read it whole. Most likely to be re-filed:

- "the patched gem's gemspec differs from the installed one" after a hosted scan: a mock gem rebuilt with `gem build` has a different gemspec. Repack with the original `metadata.gz`.
- `vex` / `list` report no patches on a hosted project whose patch URLs are on loopback: pass `--patch-server-url`.
- `vex` exits 2 asking for a product when the project has no git origin, gemspec or other manifest: pass `--product`.
- Hosted scan leaves gems in a shared gem home unpatched and warns: documented ("Ruby gems: gems already installed").
