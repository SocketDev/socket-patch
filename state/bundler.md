Harness notes: the sandbox reaches rubygems.org but not the Socket patch API. Each run writes its own mock of the patch API and registry (about 100 lines of Python): `POST …/patches/batch`, `GET …/patches/by-package/<purl>`, `POST …/patches/package` (a `tarball` artifact with `integrity.sha256` and `sha512` SRI, a `gem-stub-gemspec` artifact serving `gem spec <patched.gem> --ruby`, and a `rubygems-compact-index` `registryOverride`), `GET …/patches/view/<uuid>` (files with `beforeHash`, `afterHash`, base64 `blobContent` / `beforeBlobContent`), and a compact index under `/patch-registry/gem/<token>/<uuid>/` (copy the `/info` line from rubygems.org and swap the checksum). Request shapes: `crates/socket-patch-cli/tests/e2e_redirect_gem_stale_install.rs`. Build the patched gem without Ruby: change one file in `data.tar.gz`, keep `metadata.gz`, recompute `checksums.yaml.gz`. Pass `--api-url <mock> --patch-server-url <mock> --api-token fake --org test` to every command. Give test repos a `**/vendor/bundle/` ignore line. Agent mode needs no mock: write `.socket/manifest.json` and `.socket/blobs/<git-sha256>` by hand, with the gem's own file as `beforeHash`. Rubies are in `/opt/rbenv/versions` (3.1.6: Bundler 2.3.27, 2.6.9; 3.2.6: 2.4.19, 4.0.18; 3.3.6: 2.5.22, 4.0.18); `gem install bundler -v 4.1.0` / `4.0.24` / `1.17.3` works, and `gem update --system 4.1.0` gives RubyGems 4.1. Select a Bundler with `BUNDLER_VERSION`. A realistic project: `gem install rails -v 8.0.2` (or 7.1.5) into a scratch `GEM_HOME`, then `rails new app --skip-git --skip-bundle --skip-javascript --skip-hotwire --skip-asset-pipeline --skip-docker`; patch rack, puma, bootsnap, web-console, capybara. For a superseding patch, add a new uuid for the purl. `vex` writes with `--output` (`-o` is `--org`); `remove` takes one purl. No Ruby 3.4 / 4.0 here: ruby-build's downloads are blocked (11-18).

## Known non-bugs

The full list is in `known-non-bugs/bundler.md` on this branch. Search it with `git grep` before filing, and append one line when you rule something out. Don't read it whole. Most likely to be re-filed:

- "the patched gem's gemspec differs from the installed one" after a hosted scan: a mock gem rebuilt with `gem build` has a different gemspec. Repack with the original `metadata.gz`.
- `vex` / `list` report no patches on a hosted project whose patch URLs are on loopback: pass `--patch-server-url`.
- `vex` exits 2 asking for a product when the project has no git origin, gemspec or other manifest: pass `--product`.
- Hosted scan leaves gems in a shared gem home unpatched and warns: documented ("Ruby gems: gems already installed").
- `apply --check` out of sync for a native gem after Bundler rebuilt it (agent record + hosted pin): documented, run `apply` again.
