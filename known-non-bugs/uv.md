# Known non-bugs and documented limitations: uv (pm:uv)

Moved from state/uv.md on 2026-11-27 when the state file was compacted. Search with git grep; do not read whole.

- (run 47) `UV_EXCLUDE_NEWER_PACKAGE` doesn't filter `uv pip compile` pylocks (0.11.32 / 0.13.1), and `--exclude-newer` doesn't filter pylock files on uv ≤ 0.12.0. Neither is a restore gap.
- `UV_NO_BUILD=1` / `UV_ONLY_BINARY=six` don't filter what `uv pip compile --format pylock.toml` records (0.13.1 keeps six's sdist), so env vars aren't a #1613 lane (run 46).
- Hosted restore of a pylock whose siblings have no wheels (`--no-binary attrs`) re-renders six's single-wheel `wheels = [{ … }]` as a multi-line array. It's cosmetic (same content, uv reads it identically) and pre-existing on main. Not filed (run 46).
- uv.lock always records every artifact under `no-build` / `no-build-package` / `no-binary-package` (pyproject or `uv.toml`, 0.13.1), so the hosted restore guard reading only pyproject `[tool.uv]` is harmless for uv.lock (run 45).
- `uv export --format pylock.toml --no-build` / `--no-binary-package` still records every file (0.13.1); only `uv pip compile` pylocks filter (from 0.9.16), see #1613 (run 45).
- Hosted `scan` never follows requirements `-r` includes (quoted, escaped or plain): `redirect_requirements_entry_not_found` / `redirect_unconfirmed`, exit 0. Documented (CLI_CONTRACT `redirect_requirements_takeover_unreachable`: hosted rewrites only root pins), and it's the pip lane (run 44).
- `no-build-package` / `no-build` on the patched package: the wheel installs fine, and only the hosted restore is refused (documented). Not part of #1603 (run 44).
- A parent `[tool.uv]` holding `exclude-dependencies` / `environments` / `conflicts` / `default-groups` / `build-backend` isn't inherited by uv 0.13.1, which matches `UV_PROJECT_ONLY_KEYS` (run 44).
- Hosted VEX on a uv project with a non-Socket `six @ https://...` requirements line exits 2 `manifest_not_found` with `patched_ref_unattributable`: the wiring is withheld (#1549 behaviour), so nothing is left to attest (run 43).
- A uv workspace root under a parent config gives `redirect_uv_project_unsupported` / `pypi_uv_workspace_unsupported`: that's the general uv workspace refusal, not #1545 (run 43).
- `vex` warns `patched_ref_invalid` on a `uv pip freeze` line `six @ file:///abs/.socket/vendor/...whl` but still attests from uv.lock. The wheel it names is the patched one, so the attestation is correct (run 43).
- A parent `pyproject [tool.uv]` or `uv.toml` holding only `constraint-dependencies`, `override-dependencies`, `build-constraint-dependencies`, `environments`, `required-environments`, `dev-dependencies` or `conflicts` is NOT inherited by a child uv project (0.5.31 / 0.13.1). Shadowing it is harmless, so wiring such a child is correct (run 42).
- `vex` on a uv project whose pyproject.toml starts with a BOM refuses `product_undetected` ("has no usable name and version"), although uv accepts the file. #1529 made this deliberate; the scan writers drop the BOM, so it only shows up when the BOM is still there (agent mode, or a re-added BOM). `--product` is the workaround (run 42).
- `uv sync --locked` failing on uv ≤ 0.5.4 after transitive / constraint wiring, and a plain sync reinstalling the pristine wheel there, are documented uv limits. Only the missing hosted advisory is a bug (#1569) (run 42).
- Hosted uv rollback refuses a one-package lock ("no sibling registry package shows the registry and artifact fields") and any lock with `[options] exclude-newer`: documented restore limits (uv.rs module docs); `git checkout` restores (run 41).
- Vendored `vex` attests `not_affected` while `.venv` still holds unpatched bytes (scan without re-sync). Documented: vendored VEX hashes the committed artifact and warns `vendored_tree_out_of_sync`. Hosted refuses `not_applied` in the same state (run 40).
- A vendored scan over a #1453-orphaned hosted override (its package gone from the lock) is a silent no-op. `list` reports the orphan and `rollback` retires it (run 40).
- PEP 723 scripts in subdirectories aren't discovered from the root; scan them with `--cwd sub` or `scan sub` (run 40).
- A parent-directory `uv.toml` with `no-sources = true` above a uv project doesn't affect the project's `uv lock` / `uv sync` (0.5.31 / 0.12.24 / 0.13.0), so wiring it is correct (run 39).

- Hosted uv workspaces are refused (`hosted sources for uv workspaces require a package-scoped source mapping`), so #1445 has no workspace lane (run 39).
